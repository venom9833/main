> 최초 작성: 2026-04-30 | 설계 대화 완료: 2026-04-30
> 관련 LD: LD-003(image_hint), LD-015(HOOK 단독), LD-016(default 의상)
> 관련 파이프라인 단계: `awaiting_script_approval`

## 1. 목적

V2 59,000원 구독자(다수 사용자)가 유료 API 없이 무료·구독 요금제 이미지 생성 사이트(Gemini, ChatGPT, Ideogram 등)에서
컷별 배경 이미지를 확보하여 `/series/keyframe` 페이지로 가져오는 흐름을 단순화한다.

**핵심 원칙**: 유료 이미지 API 호출 없이 사용자의 구독 크레딧으로 이미지 확보.

## 2. 진입점 및 UI 구조

### 진입점
- 페이지: `/series/{id}` (`awaiting_script_approval` 단계)
- 위치: 대본 확인 헤더 — "대본 교정" / "키프레임 익스텐션" / "대본 재생성" 버튼 순서

### UI 패턴: 우측 슬라이드오버 (Drawer) — 확정
- **채택 이유**: 사용자가 외부 이미지 도구와 alt-tab을 반복하는 작업에서 모달보다 안정적. 대본 화면을 유지하며 작업 가능.
- 너비: 62vw (fixed, right)
- 닫기: ✕ 명시적 클릭 or overlay confirm

### 두 버튼의 관계 — 독립적
- "키프레임 익스텐션"은 선택적 보조 도구 (강제 게이트 아님)
- "대본 승인 → 키프레임 제작" 버튼은 항상 독립 동작

## 4. 핵심 설계 결정: 그리드 프롬프트 방식

### 결정 (2026-04-30)
컷 1개 → 이미지 1장 방식 **폐기**
→ **2×2 (4컷) 또는 3×3 (9컷) 그리드 프롬프트** 1개 → 그리드 이미지 1장 방식 채택

### 이유
- 70컷 기준: 개별 방식 70번 → 2×2 18번, 3×3 8번으로 사용자 번거로움 대폭 감소
- 무료 이미지 생성 도구는 생성 횟수 제한이 있으므로 묶음 생성이 유리

### 그리드 프롬프트 구조
```
{style_prefix}, {grid_label}, each panel clearly separated by thin lines,
[Panel 1, top-left] (scene_code): {컷 텍스트 100자}
[Panel 2, top-right] (scene_code): ...
Do NOT mix elements between panels.
[group: nc01~nc04]
```

### 그룹화 규칙 (LD-015 준수)
- HOOK 컷(`is_hook=true`): 그리드 제외, 단독 카드 (1컷 1장)
- 정규 컷: batchSize(4 or 9) 단위 그룹화
- 대사 컷(`type=dialogue`): 그리드 포함하되 `[BG only - lipsync MP4 needed]` 주석, 업로드 대상 제외

## 5. 이미지 분할·업로드 구조 (2026-04-30 설계 확정)

### 확정된 업로드 API
- 엔드포인트: `POST /api/v1/series/{id}/upload-grid-image`
- FormData: `file` (그리드 PNG), `scene_codes` (JSON 배열 문자열 — narration 컷만 포함)
- 동작: 그리드 → 자동 N등분 크롭 → 1920×1080 LANCZOS 리사이즈 → R2 저장 → `v3_scenes.bg_url` + `keyframe_url` 동시 업데이트
- 응답: `{ status: "ok", cut_count: N, results: [{scene_code, url, width, height}] }`

### 백엔드 구현 현황
- `services/grid_crop_service.py`: **이미 구현 완료**
  - `crop_grid()`: 4등분 크롭 → 1920×1080 LANCZOS → R2 업로드
  - `calc_crop_coords()`: 1px 단위 정밀 크롭 좌표 계산 (inner_trim=8px 구분선 제거)
  - `save_grid_to_r2()`: 그리드 원본 R2 저장 (디버깅/재크롭용)
- `routers/chapters.py` `POST /{series_id}/upload-grid-image`: **이미 구현 완료**

### 3×3 품질 — 2K 이미지로 극복 (2026-04-30 확정)

| 소스 해상도 | 3×3 분할 시 패널 크기 | 1920×1080 업스케일 배율 | 판정 |
|------------|---------------------|------------------------|------|
| 1024×576 (1K) | 341×192 | 5.6× | ❌ 화질 열화 심함 |
| 2048×1152 (2K) | 683×384 | 2.8× | ⚠️ 허용 수준 |
| 2752×1536 (Ideogram 최대) | 917×512 | **2.1×** | ✅ 웹소설 허용 범위 |
| 3072×1728 (3K) | 1024×576 | 1.9× | ✅ 양호 |

**결론**: 사용자가 Ideogram에서 최대 해상도(2752×1536)로 생성하면 3×3도 충분한 품질 확보 가능.

### 그리드 크기별 분할 설계
| 모드 | scene_codes 수 | 분할 방식 | 백엔드 상태 |
|------|--------------|---------|------------|
| 2×2 | 최대 4개 | 4등분 | ✅ 구현 완료 |
| 3×3 | 최대 9개 | 9등분 | ⬜ 미구현 — `crop_grid()` 확장 필요 |

3×3 백엔드 설계: `len(codes) ≤ 4 → 2×2` / `len(codes) ≤ 9 → 3×3` 자동 분기

### 현재 버그
> ⚠️ `ExtensionDrawer.tsx`의 `GridGroupCard.handleFileChange()`가 잘못된 API 사용 중.
> - **현재 (버그)**: `/scenes/{code}/upload` 루프 N회 → 그리드 이미지 통째로 각 컷에 동일 저장
> - **정상**: `/upload-grid-image` 단일 호출 → 자동 분할 → 각 컷에 개별 이미지 저장

### 대사 컷 처리
- `type === 'dialogue'`: scene_codes 배열에서 제외 (업로드 대상 아님)
- 립씽크 MP4는 키프레임 페이지에서 별도 처리
- **이유**: 익스텐션 책임 = 정적 배경 이미지 한정

## 7. 크롬 익스텐션 vs 웹앱 사이드 패널 — 설계 결정 (2026-04-30)

### 핵심 차이: 탭 경계 접근권

| 능력 | 웹앱 사이드 패널 (현재) | 크롬 익스텐션 |
|------|----------------------|--------------|
| 외부 사이트 텍스트 자동 입력 | ❌ 불가 | ✅ content script |
| 생성된 이미지 자동 캡처 | ❌ 불가 | ✅ 탭 간 통신 |
| 탭 전환 없이 작업 유지 | ❌ (alt-tab 반복) | ✅ Chrome Side Panel API |
| 설치 없이 즉시 사용 | ✅ | ❌ Web Store 배포 필요 |
| Camoufox(Firefox)와 호환 | ✅ | ❌ Chrome 전용 |

### 워크플로우 B 달성 수준 비교

| 단계 | 웹앱 사이드 패널 | 크롬 익스텐션 |
|------|----------------|--------------|
| 프롬프트 생성 | ✅ | ✅ |
| 사이트 열기 | ✅ window.open | ✅ tabs.create |
| 프롬프트 입력 | ❌ 수동 붙여넣기 | ✅ content script 자동 입력 |
| 이미지 생성 | 수동 (공통) | 수동 (공통) |
| 이미지 캡처 | ❌ 수동 다운로드 후 업로드 | ✅ Ideogram / ⚠️ Gemini blob URL 문제 |
| 업로드 & 분할 | ✅ upload-grid-image | ✅ upload-grid-image |

### 시간 절약 분석

```
프롬프트 생성(수초) → [붙여넣기 5초] → 이미지 생성(30~60초) → [다운로드+업로드 10초]
```

- 익스텐션이 자동화 가능한 구간: 붙여넣기 5초 + 다운로드·업로드 10초 = **그룹당 약 15초**
- 70컷 기준 18그룹 → **총 4~5분 절약**
- 실제 대기 시간의 대부분은 이미지 생성 30~60초 — 어느 방식이든 동일

### 배포 현실 비교

| | 웹앱 사이드 패널 | 크롬 익스텐션 |
|-|----------------|--------------|
| 배포 | 웹 배포와 동일 (즉시) | Web Store 심사 (수일~2주) |
| 업데이트 | 즉시 반영 | 심사 후 반영 |
| V2 구독자 온보딩 | URL 접속만 | 익스텐션 설치 안내 필요 (이탈 리스크) |
| 유지보수 | 낮음 | Manifest V3 규격 관리 필요 |

### 결정 (2026-04-30)

**Phase 1: 웹앱 사이드 패널 유지**
- 절약 시간(4~5분) 대비 익스텐션 개발·배포·유지 비용이 과다
- 59,000원 구독자 온보딩에서 "익스텐션 설치" 단계는 이탈 요인

**Phase 2: 크롬 익스텐션 + Side Panel API — 확정 (2026-04-30)**
- Google Flow 등 이미지 생성 사이트는 `X-Frame-Options: DENY`로 iframe 차단
- 크롬 익스텐션 Side Panel은 iframe이 아닌 **일반 탭 옆에 고정 패널**로 동작 → 차단 없음
- content script로 Flow·Ideogram·ChatGPT 텍스트 필드에 프롬프트 자동 입력 가능

```
[크롬 브라우저]
┌─────────────────────────────┬──────────────────┐
│  Google Flow / Ideogram     │  LinkDrop        │
│  (일반 탭 — 정상 동작)      │  Side Panel      │
│                             │  (익스텐션)      │
│  ← 사용자가 직접 조작 →    │  - 그리드 프롬프트│
│                             │  - 자동 입력     │
│                             │  - 업로드 버튼   │
└─────────────────────────────┴──────────────────┘
```

Electron/Tauri(커스텀 브라우저)와의 차이:
- Electron은 webview로 iframe 차단 우회 가능하나 앱 설치 ~150MB + 로그인 세션 재현 마찰
- 크롬 익스텐션은 사용자의 기존 크롬 + 기존 Google 로그인 그대로 활용 → 온보딩 마찰 최소

## 8. Camoufox 브라우저 연동 (Phase 2 탐색 — 확정 아님)

> 사용자 언급 의도: "이걸 사용해서 더 편한 환경이 가능한지" 탐색용. 반드시 사용 결정 아님.

### 도구 정보
- 저장소: https://github.com/jo-inc/camofox-browser
- 특징: Firefox C++ 레벨 핑거프린트 스푸핑, REST API(`localhost:9377`)
- **크롬 익스텐션과 호환 불가** (Firefox 기반)

### 반자동화 가능 플랫폼 평가
| 플랫폼 | 자동화 가능성 | 비고 |
|--------|-------------|------|
| Ideogram | ✅ 높음 | 이미지 전문, 무료 10장/일, UI 안정적 |
| ChatGPT | ⚠️ 보통 | DALL-E 무료 제한, UI 변경 빈번 |
| Gemini | ⚠️ 낮음 | Google 봇탐지 강함, **blob URL 캡처 실패 가능** |

### Gemini 특이사항
- C++ 핑거프린트 스푸핑으로 기본 봇탐지 우회 가능
- 문제: 이미지가 blob URL로 서빙 → 자동 캡처 어려움
- 해결 방향: VNC 1회 수동 로그인 → 쿠키 저장 → 이후 자동화

### Phase 2 자동화 플로우 (설계안)
```
buildGridPrompt() → camofox POST /tabs (open platform)
→ POST /tabs/{id}/type (prompt 입력)
→ POST /tabs/{id}/click (생성 버튼)
→ GET /tabs/{id}/images (결과 캡처)
→ upload-grid-image API (R2 저장 + 자동 분할)
```
