## 1. 전체 생성 흐름 (7단계)

```
[STEP 0]  챕터 청사진 생성  (Gemini 0회 — storyArc 있으면 Python 조립)
          _generate_outline()
            → storyArc 있음: Python 직접 조립 (arc + _ROLE_GUIDE 결합) — Gemini 0회
            → storyArc 없음: Gemini 호출 (fallback, temperature=0.4, max_tokens=1200)
          실패해도 STEP 1 계속 진행 (optional)
                ↓
[STEP 1]  데이터 수집
          world_data / chapter / role / prev_ending / prev_metas / emoline_edges / RAG
                ↓
[STEP 2]  대본 생성  (Gemini, temperature=0.95, max_tokens=6000)
          _build_narrative_prompt(outline_block=...) → call_gemini() → narrative
                ↓
[STEP 2.5] Python pre-check  (Gemini 0회)
          _python_lint_check() → 규칙 위반 없으면 STEP 3 전체 스킵
          체크 항목: 대사 초과 / 종결어미 3연속 / 분량 부족 / ch01 클리프행어 미감지
                ↓ (위반 있을 때만)
[STEP 3]  3-Judge 교차 검증 Lint → Gemini Revise  (조건부)
          asyncio.gather(style, structure, causality) → tickets 집계 → 임계치 초과 시 재작성
          Judge 전원 실패 시 → Gemini 단독 Lint 폴백 (_lint_and_revise_gemini_only)
                ↓
[STEP 4]  씬/컷 구조화  (Gemini, temperature=0.3, max_tokens=8000)
          _build_structure_prompt() → call_gemini() → JSON 파싱 → _parse_scenes_json()
                ↓
[STEP 5]  Pass 2 대사 흡수
          _absorb_dialogue_cuts()
            → 템플릿 우선 처리 (_template_absorb) — Gemini 0회
            → 변환 불가한 것만 Gemini 단일 배치 호출
                ↓
[STEP 6]  POST-SCRIPT: 미등록 조연 외모 자동 배정  (Gemini 0회)
          _detect_and_generate_guest_cast() → GUEST_APPEARANCE_MAP 프리셋 할당
          → world_data.guest_cast 저장
```

### 정상 경로 Gemini 호출 수

| 경로 | 호출 수 | 조건 |
|------|--------|------|
| **최적 (storyArc 있음 + pre-check 통과)** | **2회** | STEP 2 + STEP 4 (STEP 0 Python 조립, Lint 스킵) |
| storyArc 없음 + pre-check 통과 | 3회 | STEP 0(Gemini) + STEP 2 + STEP 4 |
| 위반 경로 (Judge 호출) | 4~6회 | Lint 이슈 발견 시 |
| 최악 경로 (Revise 포함) | 최대 6회 | critical 위반 + Revise 1회 |

## 4. STEP 1 — `_ROLE_GUIDE` 역할별 비트 구조

### 도입부 (ch01)
```
① 열린 이미지: 첫 문장은 주인공 현재 세계를 감각 디테일 1개로 고정. 설명 없이 장면으로만.
② 테마 암시: 누군가의 대사 또는 배경 디테일 1개가 시리즈 핵심 주제를 암묵적으로 가리킨다.
③ 주인공 설정: 주인공 A 한 명에만 집중. 최우선 목표 1개만 전면에. 조연은 이름 없이 역할로만.
④ 전환점(Catalyst): 평화로운 일상을 깨뜨리는 이상 신호 1개. 주인공이 피할 수 없게 만든다.
⑤ 논쟁(Debate): 행동할 것인가 말 것인가 — 주인공의 망설임을 행동의 지연·회피로 보여준다.
⑥ 한 장면에 한 갈등만.
⑦ 닫는 훅: 다음 화에서 일어날 구체적인 사건을 예고하는 행동/발견으로 닫는다.
```

### 전개 (ch02, ch03)
```
① 직전 챕터 마지막 장면의 감정적 여파에서 정확히 이어받아 시작한다.
② 주인공이 취한 행동이 예상치 못한 결과를 낳는다 — 갈등을 한 단계 심화.
③ 거짓말·회피 순간 1개 이상: 인물이 진실을 숨기는 행동이 씬 안에 등장한다.
④ 중간 반전(Midpoint): 챕터 절반 지점(3~4번째 씬)에서 상황이 역전되거나 새 사실이 드러난다.
⑤ 긴장은 감정 서술 대신 인물의 선택과 행동으로 보여준다.
⑥ 한 장면에 한 갈등만.
⑦ 닫는 훅: 다음 화에서 일어날 구체적인 사건을 예고하는 행동/발견으로 닫는다.
```

### 클라이맥스 (ch04, ch05)
```
① 모든 것을 잃는 순간(All Is Lost): 챕터 초반 주인공이 최악 상황에 놓인다.
② 암흑의 밤(Dark Night): 포기 vs 도전 — 주인공의 내면 갈등을 행동의 정지·역행으로 표현.
③ 핵심 갈등 폭발·충돌: 복선으로 심어둔 사실이 행동으로 터져 나온다.
④ 반전/고백 1개: 말이 아니라 행동으로 드러낸다.
⑤ prev_meta_section의 복선 1개 이상 반드시 회수한다.
⑥ 긴장은 감정 서술 대신 인물의 선택과 행동으로 보여준다.
⑦ 닫는 훅: 충돌이 남긴 돌이킬 수 없는 변화를 행동/발견으로 닫는다.
```

### 결말 (ch06)
```
① 핵심 갈등의 감정적 해소 — 승리·화해·결별 중 하나. 모호하지 않게.
② 닫는 이미지(Final Image): 1화 열린 이미지와 대비되는 장면으로 주인공의 변화를 증명한다.
③ 열린 결말 또는 완결 — 독자가 여운을 스스로 완성하게 1문장으로 닫는다.
④ 모든 것을 설명하지 않는다. 설명 없이 이미지로 끝낸다.
```

## 6. STEP 3 — 3-Judge 교차 검증 Lint + Gemini Revise

> pre-check 통과 시 이 STEP 전체가 스킵된다. (정상 대본 기준)

### 설계 원칙

> **핵심**: Gemini가 생성한 대본을 Gemini가 채점하면 같은 편향을 공유한다.
> 외부 이기종(heterogeneous) 모델 3개가 각기 다른 축을 채점 → 자기 검증 맹점 해소.

```
[asyncio.gather — 병렬 3심사관]
  Judge A (style)     → 한국어 문체 원칙 ①②⑥⑦
  Judge B (structure) → 구조 항목 ⑧⑨⑪ + 비트/대사/클리프행어/비밀표지
  Judge C (causality) → 인과·징후 원칙 ③④⑤⑩
        ↓
[issue_ticket 집계]
  각 Judge → {"tickets": [{axis, principle_id, severity, excerpt, fix_direction}]}
  중복 excerpt 발견 → severity 1단계 상향
        ↓
[Revise 트리거 판정]  — 활성 Judge 수에 따라 임계치 조정
  high ≥ 1  또는  medium ≥ N (N은 아래 표) → Gemini Revise 1회
  미달      → 원본 그대로 반환
        ↓
[Gemini Revise]  (temperature=0.7, max_tokens=6000)
  티켓 목록을 구조화된 수정 지시로 변환 → reviser.md 기반 재작성
```

### issue_ticket 스키마

```json
{
  "axis":          "style | structure | causality",
  "principle_id":  "P1~P11 | BEAT_MISS | DIAL_OVER | CLIFF_MISS | SECRET_MISS",
  "severity":      "high | medium | low",
  "excerpt":       "위반 문장 원문 30자 이내",
  "fix_direction": "수정 방향 한 문장"
}
```

### Revise 트리거 임계치 (활성 Judge 수별)

| 활성 Judge 수 | high 최소 | medium 최소 | 비고 |
|-------------|---------|-----------|------|
| 3 | 1 | 3 | 정상 운영 |
| 2 | 1 | 4 | 기준 강화 |
| 1 | 1 | 999 (사실상 high만) | 단일 Judge 오탐 방지 |
| 0 | — | — | Gemini 단독 폴백 |

### 폴백 계층

```
pre-check 통과    → Judge 전체 스킵 (정상 경로)
Judge 3개 정상    → 3-Judge 교차 검증
Judge 1~2개 실패  → 남은 Judge로 부분 검증 (임계치 자동 강화)
Judge 전원 실패   → _lint_and_revise_gemini_only() (기존 Gemini self-lint)
OPENROUTER_API_KEY 미설정 → _lint_and_revise_gemini_only() 즉시
```

## 8. STEP 3 — RAG 컨텍스트 (`build_rag_context`)

`wiki_service.py` 의 `build_rag_context()` 가 조립하는 컨텍스트:

```
1. wiki 4페이지  (token_budget 소진까지 우선 주입)
2. RAG 청크      (arc_keyword 기반 유사도 검색)
3. writing_guide 감정 패턴  (섹션 9 — 장르별 참조 데이터)
4. 퓨샷 예시 7개 (hash(series_id:chapter) 시드로 결정론적 샘플링)
```

### arc_keyword 로직

```python
_arc_keyword = (world.get("storyArc") or {}).get(f"ch{chapter:02d}", "")
rag_ctx = await build_rag_context(series_id, role, chapter, arc_keyword=_arc_keyword)

# build_rag_context 내부
query = arc_keyword.strip() or _ROLE_QUERIES.get(chapter_role, chapter_role)
```

storyArc가 없으면 역할 기본 쿼리(`_ROLE_QUERIES`)로 폴백.

## 10. STEP 5 — Pass 2 대사 흡수 (`_absorb_dialogue_cuts`)

> **설계 원칙**: 템플릿으로 처리 가능한 것은 Gemini 없이 처리. 복잡한 것만 배치 호출.

```
dialogue 컷 수 ≤ cap → 그대로 반환 (변환 없음)
dialogue 컷 수 > cap →
  보존 대상: is_hook 컷 + 앞쪽 (cap - hook수)개
  흡수 대상: 나머지
    ↓
  [1] 템플릿 처리 (_template_absorb) — Gemini 0회
      패턴: "대사 내용" → {화자}은/는 {내용}다고 말했다.
      변환 성공 → 즉시 narration으로 교체
    ↓
  [2] 변환 불가 (복잡한 구조) → Gemini 단일 배치 호출
      모아서 1번에 처리 (개별 호출 금지)
```

### `_template_absorb()` 변환 패턴

| 원문 대사 | 변환 결과 |
|----------|---------|
| `"당신이 미워요."` | `지선은 당신이 미워요다고 말했다.` |
| `"왜 그랬어요?"` | `민준은 왜 그랬어요라고 물었다.` |
| `"절대 안 돼!"` | `지선은 절대 안 돼라고 외쳤다.` |
| 복잡한 구조 (중간 서술 포함) | `None` → Gemini 배치 폴백 |
