## 발생 원인 요약

**현상**: yang_sy(charA) + kim_th(charB) 시리즈에서 대본 생성 LLM이 두 사람을 현대 기혼 부부로 묘사.
- yang_sy 프로필: 남편=최민성, 의붓아들=최재현 (family_group=family_choi)
- kim_th 프로필: 아내=한은정, 딸=김나은 (family_group=family_kim)
- storyArc 의도: ch02에서 처음 만나는 구조

**근본 원인**: casting → architect → script 3단계 모두 두 주인공의 "ch01 시점 관계 상태"를 데이터 모델로 정의·전달하지 않음. 특히 캐릭터 JSON의 `relationships` 객체(배우자, 자녀 명시)가 STEP1 프롬프트에 주입된 적 없음.

## 관계 상태 타입 정의

```python
RelationshipAtCh01Start = Literal[
    "strangers",      # 완전 모르는 사이 (다른 family_group, 로맨스 판타지 기본)
    "acquaintances",  # 아는 사이지만 가깝지 않음
    "colleagues",     # 같은 직장/조직
    "rivals",         # 경쟁 관계
    "married",        # 현재 결혼한 부부 (같은 family_group)
    "romantic",       # 연인 관계
    "family",         # 혈연 (부모-자녀, 형제 등)
    "other",          # 기타 (description 필수)
]
```

## world_data 신규 필드 6개 (LD-017)

| 필드명 | 타입 | 설명 | 결정 주체 |
|--------|------|------|-----------|
| `relationshipAtCh01Start` | str (enum) | ch01 시작 시점 두 주인공의 관계 상태 | casting 또는 architect |
| `relationshipAtCh01Description` | str | 한 줄 자유 텍스트 설명 | architect |
| `charAFamilyGroup` | str | 캐릭터 JSON의 family_group | casting (자동) |
| `charBFamilyGroup` | str | 캐릭터 JSON의 family_group | casting (자동) |
| `charARelationships` | dict | 캐릭터 JSON의 relationships 객체 전체 | casting (자동) |
| `charBRelationships` | dict | 캐릭터 JSON의 relationships 객체 전체 | casting (자동) |

### family_group 기반 결정론적 산출 규칙

```
charAFamilyGroup == charBFamilyGroup → "married" 또는 "family"  (사람이 확인)
charAFamilyGroup != charBFamilyGroup → 기본값 "strangers"
  - 로맨스/판타지 → "strangers"
  - 직장 드라마 → "colleagues" 가능
```

## 파이프라인 3-Gate 설계

### Gate 1: 캐스팅 단계 (casting_service.py)

**수정 위치**: `run_casting()` → patch 딕셔너리

추가 로직:
```python
# 캐릭터 JSON에서 relationships 로드
char_a_detail = _load_detail(charA_id)
char_b_detail = _load_detail(charB_id)
char_a_idx = idx_map.get(charA_id, {})
char_b_idx = idx_map.get(charB_id, {})

patch.update({
    "charAFamilyGroup": char_a_detail.get("family_group", ""),
    "charBFamilyGroup": char_b_detail.get("family_group", ""),
    "charARelationships": char_a_detail.get("relationships", {}),
    "charBRelationships": char_b_detail.get("relationships", {}),
    # 결정론적 초기값 (architect가 덮어쓸 수 있음)
    "relationshipAtCh01Start": _determine_initial_relationship(
        char_a_detail.get("family_group"),
        char_b_detail.get("family_group"),
    ),
    "relationshipAtCh01Description": "",  # architect에서 채움
})
```

```python
def _determine_initial_relationship(fg_a: str, fg_b: str) -> str:
    if fg_a and fg_b and fg_a == fg_b:
        return "family"   # 같은 가족 단위
    return "strangers"    # 다른 가족 → 기본 모르는 사이
```

def _fmt_relationships(rels: dict) -> str:
    if not rels:
        return "정보 없음"
    return " / ".join(f"{k}: {v[:30]}" for k, v in rels.items())

relationships_block = f"""

"""

### Gate 3: 스크립트 단계 (script_service.py)

**`_load_char_relationships(char_id)` 헬퍼 신규**:
```python
def _load_char_relationships(char_id: str) -> dict:
    """캐릭터 JSON의 relationships 객체 반환."""
    detail = _load_detail(char_id)
    return detail.get("relationships", {})
```

**`_build_narrative_prompt()` 추가 블록**:
```python
def _fmt_relationships_block(char_name: str, rels: dict) -> str:
    if not rels:
        return f"  - {char_name}: 관계 정보 없음"
    lines = [f"  - {char_name}의 현재 가족·관계:"]
    for person, desc in rels.items():
        lines.append(f"    · {person}: {desc[:60]}")
    return "\n".join(lines)

relationship_block = f"""
## ★ 두 주인공의 ch{chapter} 시작 시점 관계 (절대 변경 금지)
- 관계 상태: {world.get('relationshipAtCh01Start', 'strangers')}
- 설명: {world.get('relationshipAtCh01Description', '두 사람은 이 챕터 시작 시점에 서로를 모른다')}
{_fmt_relationships_block(world.get('charAName', 'charA'), world.get('charARelationships') or _load_char_relationships(world.get('charA', '')))}
{_fmt_relationships_block(world.get('charBName', 'charB'), world.get('charBRelationships') or _load_char_relationships(world.get('charB', '')))}

⚠️ 위 관계 상태가 "strangers"이면:
  - 이 챕터에서 charA와 charB는 같은 집에 살거나 부부·동거인·연인으로 등장하면 안 된다.
  - charA의 가족(배우자·자녀 등)이 위에 명시된 경우, charB가 그 역할을 대신하면 절대 안 된다.
  - charB는 이 챕터에서 직접 등장하지 않거나, 환영/편지/목소리 등 간접 형태로만 등장할 수 있다.
"""
```

## consistency_judge 설계 (V3-7)

**파일**: `apps/api/prompts/judges/consistency_judge.md`

**판단 기준**:
1. charA의 relationships에 명시된 배우자/가족을 charB가 대체하는가?
2. `relationshipAtCh01Start = "strangers"`인데 같은 집에 거주하거나 이미 연인/부부로 묘사되는가?
3. family_group이 다른 두 캐릭터가 동일 가정 구성원으로 등장하는가?

**운용 방식**:
- Phase 1: `_lint_and_revise()`에 4번째 Judge로 추가, 결과는 로깅만 (auto-revise 비활성)
- 1주 데이터 수집 후 false-positive율 측정 → 임계치 설정 후 auto-revise 활성화
- LLM 체인: Cerebras → NVIDIA → OpenRouter → Gemini-Free (LD-011 준수)
