## 2. 신규 워크플로우 요구사항

컷 타입(narration/dialogue) + 캐릭터 유무에 따라 **사용자가 할 일이 달라진다.**
UI는 이 차이를 명확하게 안내해야 한다.

### 컷 타입별 사용자 액션

| 컷 타입 | 캐릭터 | 사용자 할 일 | 자동화 |
|---------|--------|------------|--------|
| `narration` | 있음 | 배경 프롬프트 복사 → 생성 → 업로드 | 캐릭터 누끼 API 자동생성 |
| `narration` | 없음 | 배경 프롬프트 복사 → 생성 → 업로드 | 없음 (Ken Burns) |
| `dialogue` 1인 | — | OTS 합성 프롬프트로 이미지 생성 → 립씽크 MP4 업로드 | TTS 오디오 자동생성 |
| `dialogue` 2인+ | — | OTS 프롬프트 (화자 정면, 나머지 뒷모습) → 립씽크 MP4 업로드 | TTS 오디오 자동생성 |

## 4. 컷 그리드 변경 — 타입 컬러 도트

기존 그리드 썸네일에 **3×3px 컬러 도트** 하나만 추가.

```
[썸네일 이미지]
  좌상단: 컷 번호 (기존)
  우상단: 타입 도트 (신규)
    🔵 narration + 캐릭터 있음  → 파랑
    ⬜ narration + 캐릭터 없음  → 회색
    🟠 dialogue               → 주황
```

코드 변경 최소화 — 기존 `isHook` 배지 옆에 도트 1개 추가:

```tsx
// 기존 코드 (유지)
{s.isHook && <span style={{ fontSize: 9, color: '#f59e0b' }}>★</span>}

// 추가
<span style={{
  width: 6, height: 6, borderRadius: '50%',
  background: s.type === 'dialogue' ? '#f97316'
            : s.hasChars             ? '#6366f1'
            : '#9ca3af',
  display: 'inline-block', flexShrink: 0,
}} />
```

`s.type`, `s.hasChars` 필드 → 씬 로드 시 `scene.type`, `scene_meta.characters.length > 0` 에서 파싱.

## 7. 업로드 기능 구현

### 배경 이미지 업로드 (narration 컷)

파일 선택 → FormData → API → R2 → `bg_url` 저장

```tsx
const handleBgUpload = async (file: File) => {
  const fd = new FormData();
  fd.append('file', file);
  fd.append('target', 'bg');
  const res = await fetch(
    `${API}/series/${seriesId}/scenes/${scene.sceneCode}/upload`,
    { method: 'POST', body: fd }
  );
  const { bg_url } = await res.json();
  setScenes(prev => prev.map((s, i) =>
    i === selectedIdx ? { ...s, imageUrl: bg_url } : s
  ));
};
```

버튼 클릭 → `<input type="file" accept="image/*">` hidden input 트리거.

### 립씽크 MP4 업로드 (dialogue 컷)

동일 구조, `target: 'lipsync'` → `lipsync_url` 저장.

### 서버 API (신규 엔드포인트)

```
POST /api/v1/series/{series_id}/scenes/{scene_code}/upload
Body: multipart/form-data
  file: 이미지 또는 MP4
  target: "bg" | "lipsync" | "char"

Response:
  { ok: true, bg_url?: string, lipsync_url?: string, char_url?: string }
```

## 8. 데이터 변경 사항 (구현 완료)

### 씬 로드 시 추가 필드 (구현 완료 — 2026-04-14)

현재 `SceneParsed` 인터페이스에 추가:

```tsx
interface SceneParsed {
  // 기존 필드 (유지)
  index: number;
  sceneIndex: number;
  cutIndex: number;
  sceneCode: string;
  text: string;
  imageHint: string;
  isHook: boolean;
  estimatedSec: number;
  imageUrl: string;
  status: string;

  // ✅ 구현 완료 (2026-04-14)
  type: 'narration' | 'dialogue';   // v3_scenes.type
  hasChars: boolean;                 // scene_meta.characters.length > 0
  speaker: string;                   // v3_scenes.speaker (dialogue 컷)
  bgUrl: string;                     // v3_scenes.bg_url (배경 이미지)
  charUrl: string;                   // v3_scenes.char_url (캐릭터 누끼)
  lipsyncUrl: string;                // v3_scenes.lipsync_url (립씽크 MP4)
}
```

### 완료 판정 로직

```tsx
// 컷별 완료 여부
const isDone = (s: SceneParsed) => {
  if (s.type === 'dialogue') return !!s.lipsyncUrl;
  if (s.hasChars)            return !!s.bgUrl && !!s.charUrl;
  return                            !!s.bgUrl;
};
```

### 줄 제한

자막은 **1줄 초과 금지**. 비율별 최대 글자 수:

| 비율 | 최대 글자/줄 | `whiteSpace` |
|------|------------|-------------|
| 16:9 | **30자** | `nowrap` |
| 9:16 | **25자** | `nowrap` |

### 타이핑 효과 — 청크 단위 char-by-char (복원됨)

**설계 원칙**: 타이핑 효과 유지. 단, 청크(30/25자) 단위로 분절하여 1줄 제한 준수.

```
useSubtitleOverlay.startTyping(text, durationSec, maxCharsPerLine)
```

**동작 흐름**:
1. 텍스트를 최대 N자 청크로 분절 (문장부호 > 공백 > 강제 컷 우선순위)
2. 각 청크마다: `setTimeout` 체인으로 한 글자씩 순차 표시 (charSpeed = chunkDur × 0.8 / chunkLen)
3. 청크 타이핑 완료 → remainMs(최소 150ms) 대기 → 화면 클리어 → 50ms 후 다음 청크

**자막 위치**:
| 비율 | CSS | 비고 |
|------|-----|------|
| 16:9 | `bottom: '13%'` | 기존 8%에서 1칸(5%) 위로 이동 |
| 9:16 | `top: ${subtitleY}%` | 훅 제어 |

**호출부**:

| 위치 | 호출 | 비고 |
|------|------|------|
| `page.tsx` | `startTypingHook(text, dur, 30)` | 16:9 기준 |
| `Modal9x16.tsx` | `startTyping(scene.text, dur, 25)` | 9:16 기준 |
