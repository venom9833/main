## 1. 프롬프트 생성 흐름

```
SCRIPT (Gemini)
  → image_hint    (한국어, 컷 시각 묘사 — 실제 렌더에 사용)
  → image_prompt  (Gemini 자동 생성 — 대본 검토용 메모, 렌더 사용 금지)
      ↓
KEYFRAME (compose-prompt API)
  → prompt_composer.py
      컷 type + 캐릭터 수 기준 자동 분기
      → bg_prompt    (배경 전용 — 사용자 수동 생성용)
      → char_prompt  (캐릭터 누끼 전용 — API 자동생성용)
      → prompt       (합성 단일 — dialogue 컷 이미지용)
```

## 2. 컷 타입별 프롬프트 분기 (확정)

| type | 캐릭터 수 | `production` | `animation_type` | 반환 프롬프트 |
|------|---------|-------------|-----------------|------------|
| `narration` | 0 | `bg_only` | `ken_burns` | `bg_prompt` |
| `narration` | **1명 (서 있음)** | `split` | `parallax` | `bg_prompt` + `char_prompt` |
| `narration` | **2명+** | `composite` | `ken_burns` | `prompt` (캐릭터 포함 합성) |
| `dialogue` | 1 | `composite` | `lipsync` | `prompt` (2/3측면 클로즈업) |
| `dialogue` | 2+ | `composite` | `lipsync` | `prompt` (OTS 구도) |

**parallax 제한:**
- `split` (`char_prompt` 생성)은 **1인 서 있는 자세**만 — 앉거나 가구와 상호작용하는 컷은 자동 판별 불가, 사용자 수동 오버라이드
- `build_char_prompt()`는 `len(characters) != 1` 이면 빈 문자열 반환

### compose-prompt API 응답 필드

```json
{
  "prompt":          "합성 단일 프롬프트 (기존 호환성 유지)",
  "negative_prompt": "글로벌 화풍 + 캐릭터 + dialogue 추가 토큰",
  "art_style":       "masako | noir_oil",
  "cut_type":        "narration | dialogue",
  "has_chars":       true,
  "speaker":         "화자 이름 (dialogue 컷만)",
  "production":      "split | composite | bg_only",
  "animation_type":  "parallax | ken_burns | lipsync",
  "bg_prompt":       "배경 전용 프롬프트 (split/bg_only)",
  "char_prompt":     "캐릭터 누끼 전용 프롬프트 (split 1인만, 나머지 빈 문자열)"
}
```

## 6. dialogue 컷 구도 원칙 (확정)

### 기본 원칙 — 카메라 직시 금지

대부분의 컷에서 캐릭터가 카메라를 직접 바라보면 어색하다.
**1/3 또는 2/3 측면 구도가 자연스러운 드라마 영상의 기본이다.**

예외: 결심·선언·독백 씬에서는 `image_hint`에 "정면" 명시 시 허용.

negative 자동 추가 (dialogue 컷 전용):
```
looking at camera, direct eye contact, eye contact with viewer,
staring into camera, facing directly at viewer,
both characters in side profile, two characters facing each other symmetrically
```

---

### 1인 dialogue — 2/3 측면 클로즈업

```
구도: medium close-up, two-thirds profile view
시선: gaze directed into the scene not at lens, natural candid framing
```

---

### 2인+ dialogue — OTS (Over The Shoulder) 구도 (확정)

#### 공간 배치

```
카메라
  │
  ▼
[청자(B) — 전경, 카메라에 가까이]
  back of head and shoulders filling foreground
  face entirely hidden
  └── 화면 앞쪽을 채워 프레임 역할
        │
        ▼ (청자 어깨 너머로 화자 보임)
[화자(A) — 중경, 약간 뒤]
  two-thirds side profile, face clearly visible
  gaze directed toward the listener in front
  NOT looking at camera
```

#### 립씽크 성공 조건

| 구도 | 립씽크 |
|------|--------|
| 화자 2/3측면(중경) + 청자 후면(전경) | ✅ 성공 — 화자 얼굴 명확히 보임 |
| 화자 측면 + 청자 측면 (대칭) | ❌ 실패 — 어느 쪽 얼굴도 불명확 |
| 화자 정면 + 청자 후면 | △ 부자연스러움 (카메라 직시) |

**핵심 규칙: 청자는 반드시 후면, 화자는 반드시 2/3 측면.**

#### OTS 프롬프트 패턴 (코드 기준)

```
화자(A):
  "{identity}, standing slightly behind in midground,
   two-thirds side profile, face clearly visible,
   gaze directed toward the listener in front,
   NOT looking at camera"

청자(B):
  "{name} standing in foreground closer to camera,
   full rear view, back of head and shoulders filling foreground,
   face entirely hidden, slightly overlapping speaker in background"
```

## 7. Negative 프롬프트 조합

`build_cut_negative_prompt()` 조합 순서:

1. `art_styles[art_style].negative_prompt` (글로벌 화풍)
2. 각 캐릭터 `negative_prompt` (캐릭터 파일)
3. `dialogue` 컷 → 카메라 직시 + 양쪽 측면 대칭 방지 토큰 자동 추가
4. 토큰 단위 중복 제거 후 `, ` join

## 8. 화풍별 프롬프트 주의사항

화풍 정의 전체는 **59번 문서** 참조.

### polystyle

- **bg/캐릭터 팔레트 분리**: 배경 프롬프트(`bg_prompt_suffix`)는 7색 퍼플 팔레트(`#180A20`~`#DDDDDD`) 적용 — 캐릭터 6색 팔레트(`#111118`~`#C0392B`)와 별개
- `bg_prompt` 생성 시(`bg_only`, `split`) → `bg_prompt_suffix` 기준 7색 팔레트
- `dialogue` OTS 합성 프롬프트 → `base_style_prompt` 기준 캐릭터 6색 팔레트
- crimson red `#C0392B` — 배경 오브젝트 1개에만 (캐릭터 사용 금지)
- `photorealistic`, `smooth shading`, `gradients` negative 필수

### masako
- `::` 웨이트 문법 금지 (Midjourney 전용) — fal.ai(FLUX)는 자연어로 대체
- `--no looking at camera` → negative에 `looking at camera, eye contact, facing camera` 토큰으로 변환
- 2인 이상 씬: 인원 수 보존 문구 필수

### noir_oil
- `dark crimson` 포인트는 씬별 오브젝트 1개에만 지정 (캐릭터 파일에 저장 금지)
- `colors outside palette` 반드시 negative에 포함
- `photorealistic` 혼용 절대 금지

## 10. 4컷 그리드 이미지 생성 전략 (2026-04-17 추가)

### 개요

기존 컷별 개별 프롬프트 생성 방식과 **병행**하는 별도 기능이다. 기존 로직을 교체하지 않는다.

같은 씬(scene_index)의 c01~c04 컷을 **1장의 16:9 그리드 이미지**로 한 번에 생성한다.
생성된 그리드를 4등분 크롭 → 개별 1920×1080 이미지로 분리한다.

### 목적

| 기존 방식 | 그리드 방식 |
|----------|-----------|
| 1컷 = 1 API 호출 | 4컷 = 1 API 호출 |
| 씬 내 색감/조명/캐릭터 불일치 | 동일 생성 컨텍스트 → 씬 내 일관성 자동 확보 |

### 그리드 레이아웃

```
c01 (좌상) | c02 (우상)
-----------+-----------
c03 (좌하) | c04 (우하)
```

전체 그리드 16:9 → 크롭 후 각 셀도 16:9 (수학적 보장)
→ 크롭 후 AI 업스케일(fal-ai/aura-sr 등)로 1920×1080 최종 해상도 확보

### 그리드 프롬프트 구조

```
{base_style_prompt},
2x2 storyboard panel layout, no borders no dividing lines no frames no separators between panels, seamless borderless composition,
top-left panel: {cut1 build_cut_image_prompt 결과},
top-right panel: {cut2 build_cut_image_prompt 결과},
bottom-left panel: {cut3 build_cut_image_prompt 결과},
bottom-right panel: {cut4 build_cut_image_prompt 결과},
consistent lighting and color palette across all four panels, no text no watermark
```

> ★ 패널 간 경계선 없음 — `no borders no dividing lines no frames no separators` 필수. 경계선 지시 입력 시 패널 구분선이 이미지에 렌더링됨.

3컷 씬: 4번째 패널 자리에 `empty scene same background atmosphere` 삽입, 크롭 후 버림.

### API 엔드포인트

```
POST /api/v1/series/{series_id}/compose-grid-prompt
Body: { scene_codes: ["ch01s02nc01", "ch01s02nc02", "ch01s02nc03", "ch01s02nc04"] }
Response: {
  grid_prompt:   str,      # 4컷 통합 그리드 프롬프트
  cut_count:     int,      # 실제 포함 컷 수 (3~4)
  scene_codes:   [str],    # 처리된 scene_code 목록
  art_style:     str       # 적용된 화풍
}
```

### UI 배치

`/series/keyframe` 페이지의 **인 확정 버튼 아래, 배경 프롬프트 위** 영역에 배치.

1. "🔲 4컷 그리드 프롬프트" 버튼 클릭
2. 현재 선택된 컷의 `scene_index`를 기준으로 같은 씬의 컷 4개(또는 3개) 자동 수집
3. `compose-grid-prompt` API 호출
4. 결과 textarea에 그리드 프롬프트 출력 + 복사 버튼

### 크롭 파일명 규칙 (★ 혼선 방지)

DB `scene_code`는 타임스탬프 prefix가 붙는다 (`20260413_095022_ch01s02nc01`).
그리드 크롭 결과 파일은 **이 규칙을 따르지 않는다.**
`ch##s##nc##` 형식만 사용한다.

```
그리드 원본:  v3/{series_id}/keyframes/ch01_s02_grid.png
크롭 컷:     v3/{series_id}/keyframes/ch01s02nc01.png
             v3/{series_id}/keyframes/ch01s02nc02.png
             v3/{series_id}/keyframes/ch01s02nc03.png
             v3/{series_id}/keyframes/ch01s02nc04.png
```

타임스탬프는 DB 내부 식별자용이며, 생성 파일명에는 포함하지 않는다.

위 4가지 케이스 중 하나로 컷별 프롬프트를 생성한 뒤:


[base_style_prompt]                          ← 1회만, 그리드 헤더
"2x2 storyboard panel layout, no borders..." ← 경계선 제거 지시

  → guest_cast dict             (미등록 조연)
  → "a person named {이름}"     (최후 폴백)
현재 구조상 문제점 1개: narration + 캐릭터 있음 케이스에서 image_hint 앞에 bg_context(한국어)가 붙는다. location="최민성의 사무실", atmosphere="긴장감" 같은 한국어 토큰이 영문 프롬프트에 그대로 섞여 들어간다. 현재는 Gemini가 한/영 혼용을 처리하고 있으나, 순수 영문 프롬프트 API(fal.ai)에서는 노이즈가 될 수 있다.
