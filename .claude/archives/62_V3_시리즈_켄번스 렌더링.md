## 1. 씬 MP4 구성 원칙 (확정)

### 씬 = 립씽크 컷 + 패럴랙스/Ken Burns 컷의 조합

```
씬 MP4
  ├── 컷 (narration, 캐릭터 있음) → 패럴랙스 MP4
  │     배경(수동) + 캐릭터 누끼(API) — 2레이어 분리
  │
  ├── 컷 (narration, 캐릭터 없음) → Ken Burns MP4
  │     배경(수동) 단일 이미지 — 줌+패닝
  │
  ├── 컷 (dialogue)               → 립씽크 MP4 (사용자 수동 제작)
  │     합성 단일 이미지 — 레이어 분리 없음
  │
  └── ...

→ 전체 FFmpeg concat → 씬 MP4 완성
```

### 컷 비율 전략 (확정)

| type | 캐릭터 수 | `production` | `animation_type` | 이미지 제작 |
|------|---------|-------------|-----------------|------------|
| `narration` | **1명 (서 있음)** | `split` | `parallax` | 배경(수동) + 캐릭터 누끼 1명(API) |
| `narration` | **2명+** | `composite` | `ken_burns` | 캐릭터 포함 합성 1장(수동) |
| `narration` | **없음** | `bg_only` | `ken_burns` | 배경 1장(수동) |
| `dialogue` | — | `composite` | `lipsync` | OTS 합성 1장(수동) |

- `dialogue` 컷 30% 룰 대본 생성 시 강제 적용됨 → 비율 자동 충족
- parallax는 **1인 + 서 있는 구도**에만 적용 — 앉거나 가구와 상호작용하는 컷 제외

### 자동 분기 기준

```python
# compose-prompt API 기준 (production / animation_type 판정)
if cut_type == "dialogue":
    production, animation_type = "composite", "lipsync"
elif len(char_names) == 1:
    production, animation_type = "split", "parallax"
elif len(char_names) >= 2:
    production, animation_type = "composite", "ken_burns"
else:
    production, animation_type = "bg_only", "ken_burns"
```

**`v3_scenes.type` + `scene_meta.characters` 두 필드만으로 분기 완성.**

### parallax 적용 가능 조건

| 조건 | parallax 가능 여부 |
|------|------------------|
| 캐릭터 1명 + 서 있는 자세 | ✅ 가능 |
| 캐릭터 1명 + 앉아 있음 (소파·의자) | ❌ 불가 — Ken Burns로 처리 |
| 캐릭터 1명 + 가구·소품과 상호작용 | ❌ 불가 — 합성 어색함 |
| 캐릭터 2명+ | ❌ 불가 |

→ 자동 판별 불가. 사용자가 `image_hint` 확인 후 키프레임 UI에서 수동 오버라이드 가능.

### 립씽크 컷 이미지 구도 원칙 (확정)

#### 기본 원칙 — 카메라 직시 금지

대부분의 컷에서 캐릭터가 카메라를 직접 바라보면 어색하다.
**1/3 또는 2/3 측면 구도가 자연스러운 드라마 영상의 기본이다.**

예외: 결심·선언·독백 씬에서는 `image_hint`에 "정면" 명시 시 허용.

#### 1인 dialogue — 2/3 측면 클로즈업

```
구도: medium close-up, two-thirds profile view
시선: gaze directed into the scene not at lens, natural candid framing
```

→ 혼자 소파에 앉아 대사하는 씬에서도 카메라 직시 없이 자연스럽게 처리.

#### 2인 이상 dialogue — OTS (Over The Shoulder) 구도

```
카메라
  │
  ▼
[청자(B) — 전경, 카메라에 가까이]
  back of head and shoulders filling foreground
  face entirely hidden
  └── 화면 앞쪽을 채워 프레임 역할
        │
        ▼ (청자 어깨 너머로 화자 보임)
[화자(A) — 중경, 약간 뒤]
  two-thirds side profile, face clearly visible
  gaze directed toward the listener in front
  NOT looking at camera
```

| 구도 | 립씽크 |
|------|--------|
| 화자 2/3측면(중경) + 청자 후면(전경) | ✅ 성공 — 화자 얼굴 명확히 보임 |
| 화자 측면 + 청자 측면 (대칭) | ❌ 실패 — 어느 쪽 얼굴도 불명확 |
| 화자 정면 + 청자 후면 | △ 부자연스러움 (카메라 직시) |

**핵심 규칙: 청자는 반드시 후면, 화자는 반드시 2/3 측면.**

OTS 프롬프트 패턴 (코드 기준):
```
화자(A):
  "{identity}, standing slightly behind in midground,
   two-thirds side profile, face clearly visible,
   gaze directed toward the listener in front,
   NOT looking at camera"

청자(B):
  "{name} standing in foreground closer to camera,
   full rear view, back of head and shoulders filling foreground,
   face entirely hidden, slightly overlapping speaker in background"
```

Negative 자동 추가 (dialogue 컷 전용):
```
looking at camera, direct eye contact, eye contact with viewer,
staring into camera, facing directly at viewer,
both characters in side profile, two characters facing each other symmetrically
```

> 상세 프롬프트 조합 로직 → **61번 문서** 참조.

## 3. 패럴랙스란 무엇인가

**시차(視差) 효과** — 가까운 물체는 빠르게, 먼 물체는 느리게 움직여 보이는 자연 현상.

```
차창 밖을 볼 때:
전봇대 (가까움)  → 빠르게 지나감
산       (멂)   → 느리게 지나감
```

패럴랙스 자체는 **움직임의 원리(시각 효과)** 이며,
레이어 분리는 2D 이미지에서 패럴랙스를 **구현하기 위한 수단**이다. 별개의 개념.

```
실제 영상 (3D)   → 패럴랙스 자연 발생 (카메라가 움직이면 됨)
정지 이미지 (2D) → 모든 픽셀이 같은 평면 → 패럴랙스 없음
                   레이어 분리 후 독립 속도 적용해야 흉내 가능
```

## 4. Ken Burns vs 패럴랙스 비교

| 항목 | Ken Burns | 패럴랙스 |
|------|-----------|---------|
| 방식 | 이미지 전체가 하나의 덩어리로 이동 | 레이어별 독립 속도로 이동 |
| 깊이감 | 없음 | 있음 (3D 공간 착각) |
| 이미지 수 | 1장 | 레이어 분리 필요 (2~3장) |
| 렌더 부하 | 낮음 | 2~3배 |
| 몰입감 | 낮음 | 높음 |
| 구현 난도 | 쉬움 | 중간 |

**결론**: 유튜브 드라마 채널에서 고품질로 보이는 영상 대부분이 패럴랙스 기법 사용.
Ken Burns는 "AI 생성 영상"처럼 보이는 주원인 중 하나.

## 5. 패럴랙스 레이어 구조

```
2-레이어 (기본)                   3-레이어 (선택)

Layer 2: 배경 (야경, 벽, 하늘)   Layer 3: 배경          → 속도 0.3x
Layer 1: 캐릭터 누끼 (투명 PNG)  Layer 2: 캐릭터 누끼   → 속도 0.7x
                                  Layer 1: 전경 소품 누끼 → 속도 1.0x
```

가까운 레이어가 빠르게 → 먼 레이어가 느리게 → 깊이 착각 발생

## 6. 레이어 분리 방법 — Plan A (우선 시도)

### 원칙: 배경 수동 + 캐릭터 API 자동 (하이브리드)

| 레이어 | 제작 방식 | 이유 |
|--------|----------|------|
| **배경** | 프롬프트 출력 → **사용자 수동 생성** | 씬마다 달라서 품질 직접 확인 필요 |
| **캐릭터** | **API 자동 생성** → rembg 누끼 | 캐릭터 JSON 고정값 → 안정적 자동화 가능 |

### 구현 방법

#### Step 1 — 배경 프롬프트 출력 (수동 생성)

`compose-prompt` 엔드포인트가 배경 전용 프롬프트를 반환한다.
사용자는 이 프롬프트를 fal.ai / Replicate 웹 UI에 붙여넣어 직접 생성한다.

```python
# prompt_composer.py — char_parts가 비어 있으면 bg_prompt_suffix 사용
if char_parts:
    style_part = style_cfg.get("base_style_prompt")
else:
    style_part = style_cfg.get("bg_prompt_suffix")  # "no people, empty scene, ..."
```

```
UI 플로우:
  [배경 프롬프트 복사] → fal.ai 웹 UI → 이미지 생성 → [R2에 업로드]
  → scene_{code}_bg.png
```

**이미 구현된 경로.** 신규 개발 불필요.

#### Step 2 — 캐릭터 이미지 API 자동 생성

캐릭터 JSON(`fal_identity_prompt` + `wardrobe_prompt`)으로 프롬프트를 조합하고
단색 배경으로 API 자동 생성한다.

```python
# 캐릭터 프롬프트 끝에 단색 배경 지시 추가
char_prompt = build_cut_image_prompt(scene, art_style, guest_cast=guest_cast)
char_prompt += ", on plain white background, isolated character, full body"

# Replicate FLUX 2 Pro 호출 (fal_backend.py)
png_bytes = await fal_backend.generate(char_prompt, art_style=art_style)
```

→ API 자동으로 단색 배경 캐릭터 이미지 생성

#### Step 3 — rembg로 캐릭터 배경 제거 (무료, 로컬)

```bash
pip install rembg[gpu]   # GPU 있으면 gpu, 없으면 rembg
```

```python
from rembg import remove
from PIL import Image
import io

# API 응답 bytes → rembg → 투명 PNG
char_img = Image.open(io.BytesIO(png_bytes))
cutout   = remove(char_img)          # RGBA — 배경 투명
buf = io.BytesIO()
cutout.save(buf, format="PNG")
cutout_bytes = buf.getvalue()
```

→ 캐릭터 투명 PNG (누끼) 완성, 추가 비용 없음

#### Step 4 — R2 저장

```
R2 경로:
  series/{id}/ch{N}/scene_{code}_bg.png       ← 배경 (사용자 업로드)
  series/{id}/ch{N}/scene_{code}_char.png     ← 캐릭터 누끼 (API 자동 저장)
```

#### Step 5 — Remotion 2-레이어 애니메이션

**배경 슬라이드 + 캐릭터 줌인** 조합 (1차 구현 목표)

```
배경:      왼쪽 → 오른쪽 슬로우 슬라이드  → "세계가 흘러가는" 느낌
캐릭터:    중앙 기준 슬로우 줌인           → "클로즈업되는" 드라마 느낌
```

```tsx
const frame = useCurrentFrame();
const { durationInFrames } = useVideoConfig();
const progress = frame / durationInFrames;  // 0 → 1

// 배경: 왼쪽 → 오른쪽 슬로우 슬라이드 (±5% 이동)
const bgX = interpolate(progress, [0, 1], [-5, 5]);

// 캐릭터: 슬로우 줌인 (1.0 → 1.08)
const charScale = interpolate(progress, [0, 1], [1.0, 1.08]);

return (
  <AbsoluteFill>
    {/* 배경: 좌→우 슬라이드, 여백 보정을 위해 110% 너비 */}
    <Img src={bgUrl} style={{
      width: "110%",
      left: `${bgX}%`,
      position: "absolute",
      height: "100%",
      objectFit: "cover",
    }} />
    {/* 캐릭터 누끼: 발 기준 줌인 → 위로 자연스럽게 커짐 */}
    <Img src={charUrl} style={{
      transform: `scale(${charScale})`,
      transformOrigin: "center bottom",
      position: "absolute",
      bottom: 0,
    }} />
  </AbsoluteFill>
);
```

**`transformOrigin: "center bottom"`** — 발 기준 줌인으로 캐릭터가 위로 성장하는 느낌.
`"center center"` 로 바꾸면 중앙 기준 줌인.

**향후 강화 옵션** (필요 시 추가):
- 배경 슬라이드 방향을 씬마다 좌→우 / 우→좌 교차 → 단조로움 방지
- 캐릭터 미세 translateY(-3px ~ 0) 추가 → 떠오르는 느낌

## 8. 자동화 파이프라인 목표 구조

### Plan A 파이프라인 (우선) — 3-way 분기

```
컷 데이터 로드
      ↓
      ┌─────────────────────┬──────────────────────┬──────────────────┐
      │  dialogue           │  narration           │  narration       │
      │  (type=dialogue)    │  + characters 있음   │  + characters 없음│
      │                     │                      │                  │
      │  [립씽크 슬롯]      │  [패럴랙스]          │  [Ken Burns]     │
      │  사용자 MP4 업로드  │                      │                  │
      │  대기               │  배경 프롬프트 출력  │  배경 프롬프트   │
      │                     │  → 사용자 수동 생성  │  출력 → 수동 생성│
      │                     │  → R2: _bg.png       │  → R2: _bg.png   │
      │                     │                      │                  │
      │                     │  캐릭터 API 자동생성 │  (캐릭터 없음)   │
      │                     │  → rembg 누끼        │                  │
      │                     │  → R2: _char.png     │                  │
      │                     │                      │                  │
      │                     │  Remotion:           │  Remotion:       │
      │                     │  배경 슬라이드       │  Ken Burns       │
      │                     │  + 캐릭터 줌인       │  (줌+패닝)       │
      └─────────────────────┴──────────────────────┴──────────────────┘
                                          ↓

```

## 9. 립씽크 컷 (dialogue 30%) — 사용자 수동 제작

### 제작 방식 (확정)

`dialogue` 컷은 **사용자가 직접 편집**한다. 자동화 대상 아님.

```
시스템이 제공하는 것:
  - TTS 오디오 파일 (edge-tts 자동 생성)
  - 캐릭터 얼굴 클로즈업 이미지 (API 자동 생성)
  - 대사 텍스트

사용자가 하는 것:
  - 위 재료를 CapCut / DaVinci / Premiere 등으로 조합
  - 립씽크 클립 MP4로 저장 → 시스템에 업로드
```

### 시스템 지원 인터페이스

```
UI: dialogue 컷 목록 → [파일 업로드] 버튼
  → 업로드된 MP4 → R2 저장: scene_{code}_lipsync.mp4
  → 최종 concat 시 해당 슬롯에 자동 삽입
```

### 캐릭터 이미지 자동 생성 (사용자 편집 재료)

```python
# type == "dialogue" 컷 → build_char_prompt() 사용
# 캐릭터 전신 + 단색 배경 프롬프트 자동 조합
char_prompt = build_char_prompt(scene, art_style, guest_cast)
# → "on plain white background, isolated character, full body, no background elements"
# FLUX API 호출 → rembg 배경 제거 → R2 저장: scene_{code}_char.png
```

> 구체적인 프롬프트 조합은 `prompt_composer.build_char_prompt()` 구현 참조.

### 향후 자동화 옵션 (미정)

masako / noir_oil 삽화 화풍에서 실사 립싱크 모델(LatentSync, MuseTalk)은 화풍 불일치 우려.
자동화 필요성이 생기면 스프라이트 애니메이션(Remotion) 방식을 우선 검토.

## 15. 켄번스 재생성 버튼 — 단일 컷 처리 로직 (2026-04-18 확정)

### 분기 흐름도

재생성 버튼 클릭 시 `single_kenburns(overwrite=True)` 호출. 아래 순서로 분기한다.

```
MP3 존재?
  ├── NO  → {"ok": false, "reason": "mp3 없음"}  ← TTS 먼저 완료 필요
  └── YES → mp3 duration 측정
              ↓
              MP4 존재 + overwrite=True?
              ├── lipsync_url 있음 → [Hybrid Overwrite]
              │     R2 원본 lipsync 다운로드 → tail 계산 후 합성
              └── lipsync_url 없음 → 기존 MP4 삭제 → [일반 Ken Burns]
                                                          ↓
              MP4 없음 → [일반 Ken Burns]

              MP4 존재 + overwrite=False?
              ├── mp4_dur >= mp3_dur - 0.5 → 스킵 (길이 충분)
              └── mp4_dur < mp3_dur - 0.5  → [Hybrid 모드]
```

### Hybrid 모드 — MP4 길이 < MP3 길이일 때

기존 MP4(lipsync 또는 이전 kenburns)가 TTS보다 짧을 때 자동 적용.

```
[기존 MP4]  ──────────────────────  mp4_dur 초
                                    ↓
[Ken Burns Tail]  ──────────────── (mp3_dur + 0.5 - mp4_dur) 초
                                    ↓
FFmpeg concat → 최종 MP4
총 길이 = mp3_dur + 0.5 초
```

- `tail <= 0.5초` 이면 스킵 (충분한 길이로 간주)
- Ken Burns 효과: 짝수 scene_index → `zoom_in` / 홀수 → `zoom_out`

### 파일명 규칙 (2026-04-18 확정)

DB raw scene_code → `_normalize_scene_code()` → `ch##s##nc##` 형식으로 변환 후 파일 I/O에 사용.

```
DB scene_code:  "20260413_095022_ch01s07hc04"
file_code:       "ch01s07hc04"

입력: {output}/{series_code}/ch01/ch01s07hc04.png   ← 키프레임 이미지
      {output}/{series_code}/ch01/ch01s07hc04.mp3   ← TTS
출력: {output}/{series_code}/ch01/ch01s07hc04.mp4   ← 최종 영상
```

DB 쿼리는 raw scene_code 사용, 파일 I/O만 file_code 사용 — 두 값 혼용 금지.

## 16. 챕터 단위 최종 MP4 합성 파이프라인 (2026-04-19 확정)

### 3단계 구조

```
각 컷 mp4 완성 (kenburns_service)
        ↓
  [1단계] 표준화 재인코딩 (_normalize_clip)
          libx264 crf18 / 30fps / 1920×1080 / aac 44100
          ← 파라미터 강제 통일. 모든 소스 타입 대응:
            ken_burns / hybrid / 사용자 교체 mp4 / lipsync 원본
        ↓
  [2단계] scene_code 순 concat (-c copy)
          표준화 완료 후 -c copy 안전 보장
        ↓
  [3단계] 챕터 단위 최종 MP4
          output/{series_code}/ch{N}/ch{N}_final.mp4
```

### 설계 근거 — 왜 전체 일괄 concat이 위험한가

| 위험 요소 | 내용 |
|----------|------|
| 코덱 파라미터 불일치 | ken_burns(crf18) / lipsync 교체(외부 코덱) 혼재 |
| timebase 불일치 | `-c copy` 시 AV sync 깨짐 또는 전체 실패 |
| SAR(샘플 종횡비) 차이 | 외부 mp4 교체 후 SAR가 다를 경우 concat 아티팩트 |
| 무음 트랙 미존재 | ken_burns mp4는 오디오 없음 → concat 불가 |

→ **normalize 단계에서 모두 해소** — 이후 concat은 항상 안전.

### TTS 씹힘 방지 (+0.5s 규칙)

```
일반 Ken Burns:  total_dur = mp3_dur + 0.5s
Hybrid 모드:     total_dur = mp3_dur + 0.5s
kb_mode skip:    mp4_dur >= mp3_dur (충분 — 그대로 사용)
```

→ 모든 컷 mp4는 TTS 길이보다 최소 0.5초 이상 길게 생성됨.

### API 엔드포인트

```
POST /api/v1/series/{series_id}/chapters/{chapter}/render
```

응답:
```json
{
  "ok": true,
  "output": "/abs/path/ch01_final.mp4",
  "clips": 42,
  "missing": ["ch01s03nc02"]
}
```

- `missing`: mp4 없어서 제외된 컷 목록 (TTS/켄번스 미완료 컷)
- `output`: 로컬 절대 경로 (서버 파일시스템)

| 파일 | 역할 |
|------|------|
| `services/render_service.py` | `_normalize_clip()` / `_concat_clips()` / `render_chapter()` |
| `routers/chapters.py` | `POST /render` 엔드포인트 |
