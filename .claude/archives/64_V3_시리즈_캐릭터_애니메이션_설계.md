## 핵심 철학

> **"Ken Burns + 패럴랙스로는 절대 충분하지 않다"** — 컷별 실제 캐릭터 움직임이 필요하다.

배경 이미지의 정지 + 줌 대신, **실제 캐릭터가 등장하고 입을 벙긋하는 인형극 구조**로 전환.
정적인 슬라이드쇼에서 살아있는 연극 무대로의 전환.

## 1. 비주얼 방향 (2026-04-16 확정)

| 항목 | 결정 |
|------|------|
| 배경 | 2D 배경 이미지 (기존 masako / noir_oil 화풍 유지 가능) |
| 캐릭터 | **3D 캐릭터** (TRELLIS.2 등 3D 생성 도구로 제작한 누끼 이미지) |
| 애니메이션 | 양쪽에서 슬라이드 인 + 입 뻐끔 오버레이 |
| 구조 | 인형극 (Puppet Theater) — 배경 고정, 캐릭터만 움직임 |

기존 화풍(masako / noir_oil)은 **배경**에만 적용.
캐릭터는 3D 스타일로 화풍과 무관하게 독립 생성.

## 3. PuppetDialogueScene — 인형극 구조

### 3.1 컴포넌트 구조

```
AbsoluteFill
  ├── 배경 이미지 (ken-burns: scale 1.0 → 1.03)
  ├── 캐릭터 A (좌측 슬라이드 인)
  │     └── MouthOverlay A (sine 입 오버레이)
  ├── 캐릭터 B (우측 슬라이드 인)
  │     └── MouthOverlay B (sine 입 오버레이)
  └── Audio
```

### 3.2 Props 인터페이스

```typescript
interface CharacterConfig {
  url: string;          // R2 누끼 PNG URL
  mouthXRatio: number;  // 입 중심 X (원본 이미지 폭 기준 0~1)
  mouthYRatio: number;  // 입 중심 Y (원본 이미지 높이 기준 0~1)
  mouthWRatio: number;  // 입 폭 (charW 기준 0~1)
  mouthHRatio: number;  // 입 최대 열림 높이 (charDisplayH 기준 0~1)
  flip?: boolean;       // 좌우 반전 (기본 false)
}

interface PuppetDialogueSceneProps {
  bgUrl: string;
  charA: CharacterConfig;  // 좌측 캐릭터
  charB: CharacterConfig;  // 우측 캐릭터
  audioUrl: string;
  charDisplayH?: number;   // 캐릭터 표시 높이 px (기본 750)
}
```

### 3.3 슬라이드 인 애니메이션

```typescript
// Spring 기반 — 유리 공 튀어오르는 느낌 (damping=16, stiffness=120)
const slideA = spring({ frame, fps, config: { damping: 16, stiffness: 120 } });
const slideB = spring({ frame, fps, config: { damping: 16, stiffness: 120 } });

// A: 화면 왼쪽 바깥 → 최종 위치 (left: 60px)
charALeft = interpolate(slideA, [0, 1], [-charW - 20, 60])

// B: 화면 오른쪽 바깥 → 최종 위치 (right: 60px)
charBLeft = interpolate(slideB, [0, 1], [width + 20, width - charW - 60])
```

### 3.4 입 오버레이 — MouthOverlay

```typescript
// sine 파형으로 입 열림/닫힘 시뮬레이션
const MOUTH_FREQ = 0.28;  // ~1.3Hz = 자연스러운 말하기 속도
const sineVal   = Math.abs(Math.sin(frame * MOUTH_FREQ));
const mouthOpen = Math.pow(sineVal, 1.4);  // 0~1 (거듭제곱으로 닫힌 구간 더 길게)

const mouthH = MOUTH_MIN_H + mouthOpen * (MOUTH_MAX_H - MOUTH_MIN_H);
// 어두운 타원 — 실제 입 색상 시뮬레이션
backgroundColor: "#1a0808"
borderRadius: "50%"
```

**입 좌표 계산:**
```
rawX = charLeft + charW * mouthXRatio   (flip 시 1 - mouthXRatio)
rawY = charTop  + charH * mouthYRatio
```

### 3.5 캐릭터 크기·배치 기본값

| 파라미터 | 기본값 | 설명 |
|---------|--------|------|
| `charDisplayH` | 750px | 1920×1080 기준 화면 높이의 69% |
| `ASPECT` | 0.6 | 캐릭터 이미지 가로/세로 비율 (300:500) |
| `charW` | 450px | `charDisplayH × ASPECT` |
| 캐릭터 상단 | 330px | `1080 - charDisplayH` (화면 하단 기준) |
| A 최종 left | 60px | 좌측 여백 |
| B 최종 left | `1920 - 450 - 60 = 1410px` | 우측 여백 |

## 4. 입 좌표 캘리브레이션

### 4.1 기준 원칙

모든 비율은 **원본 캐릭터 이미지** (300×500) 기준.
렌더링 크기(750px)에 자동으로 스케일됨.

### 4.2 OpenCV 얼굴 검출로 자동 추정

```python
import cv2
img = cv2.imread("char.png")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
face_cascade = cv2.CascadeClassifier(cv2.data.haarcascades + 'haarcascade_frontalface_default.xml')
faces = face_cascade.detectMultiScale(gray, 1.1, 4)
# → (x, y, w, h) 반환
# 입 Y 추정: y + h * 0.8  ← 얼굴 높이 80% 지점
# 입 X 추정: x + w / 2    ← 얼굴 중앙
```

### 4.3 화풍별 검출 한계

| 스타일 | OpenCV Haar 검출 | 수동 보정 필요 |
|--------|-----------------|---------------|
| 2D 만화 (manhwa) | ✅ 검출 가능 | 낮음 |
| 3D 셀셰이딩 | ❌ 검출 불가 | **필수** |
| masako 화풍 | △ 불안정 | 중간 |

→ 3D 캐릭터는 밝기 분포 분석으로 얼굴 위치 추정 후 수동 확인 필요.

### 4.4 파라미터 기본값 (render.mjs 확정)

| 파라미터 | charA 기본값 | charB 기본값 | 의미 |
|---------|-------------|-------------|------|
| `mouthXRatio` | 0.47 | 0.50 | 얼굴 중앙 약간 좌/정중앙 |
| `mouthYRatio` | 0.19 | 0.21 | 얼굴 상단 19~21% 위치 |
| `mouthWRatio` | 0.07 | 0.07 | charW의 7% (약 31.5px) |
| `mouthHRatio` | 0.03 | 0.03 | charDisplayH의 3% = 최대 22.5px |

> **mouthWRatio 경고**: 0.28 이상 사용 시 입이 얼굴 전체를 덮음 (테스트에서 확인).
> 0.07~0.10 범위가 자연스러운 입 크기.

## 5. 캐릭터 누끼 (투명 PNG) 제작

### 5.1 rembg 자동 배경 제거

```python
from rembg import remove
from PIL import Image

img = Image.open("char_original.png")
cutout = remove(img)  # RGBA — 배경 투명
cutout.save("char_cut.png")
```

**설치:**
```bash
pip install rembg[gpu]   # GPU 있으면 gpu, 없으면 rembg만
```

### 5.2 원본 이미지 품질 요구사항

| 조건 | 권장 |
|------|------|
| 배경 | **순백색** (RGB 255,255,255) — 색상 잔여물 방지 |
| 캐릭터 자세 | 정면 또는 2/3 측면 (카메라 직시 허용) |
| 이미지 크기 | 300×500 또는 비율 유지 600×1000 |
| 파일 형식 | PNG (투명 배경 저장 가능) |

> TRELLIS.2 뷰어 스크린샷 사용 시: 흰 배경 씬에서 캡처 후 rembg 적용.

### 5.3 TRELLIS.2 워크플로우

```
1. 캐릭터 참조 이미지 준비 (얼굴 정면 + 의상 설명)
2. TRELLIS.2 (huggingface.co/spaces/microsoft/TRELLIS.2) 업로드
3. 3D 뷰어에서 정면/2/3측면 각도 선택
4. 스크린샷 → rembg 누끼 적용
5. R2 업로드 → render.mjs에 charAUrl/charBUrl로 전달
```

> TRELLIS.2 GLB 직접 사용 불가: Gaussian Splat 기반 → 헤드리스 렌더링 차단
> (Windows OSMesa 없음, Blender 바이너리 없음 — 2026-04-16 확인)

## 6. PixiSpriteScene (서브 방식)

### 6.1 구조

비가 내리는 PixiJS 파티클 + 3-state 스프라이트 교체 방식.
`dialogue` 컷보다 단일 캐릭터 `narration` 컷에 적합.

```
스프라이트 상태:
  idle  — 기본 서 있는 자세 (0.7s 주기)
  blink — 눈 감은 자세 (0.15s 주기)
  talk  — 입 벌린 자세 (sine 파형 교체)

PixiJS:
  rain — 180개 파티클, 결정론적 (frame 시드 기반)
```

### 6.2 Props

```typescript
interface PixiSpriteSceneProps {
  bgUrl:    string;  // 배경 이미지
  idleUrl:  string;  // 기본 스프라이트
  blinkUrl: string;  // 눈 감은 스프라이트
  talkUrl:  string;  // 입 벌린 스프라이트
  audioUrl: string;
}
```

### 6.3 3-state 이미지 요구사항

| 상태 | 이미지 설명 |
|------|------------|
| `idle` | 입 닫힌 기본 자세 |
| `blink` | 눈 감은 자세 (입 닫힘) |
| `talk` | 입 벌린 자세 |

> Flux Schnell로 각 상태 생성 시: 배경 순백색 + rembg 누끼 적용 필요.
> 3장 모두 동일 캐릭터여야 하므로 일관성 확보가 핵심 과제.

### 6.4 PixiJS + Remotion 연동 핵심 패턴

```tsx
// 비동기 초기화 — Remotion의 delayRender/continueRender 사용 필수
const [handle] = useState(() => delayRender("PixiJS 초기화"));

useEffect(() => {
  (async () => {
    const PIXI = await import("pixi.js");
    const app = new PIXI.Application();
    await app.init({ canvas: canvasRef.current!, backgroundAlpha: 0 });
    // ... 파티클 설정 ...
    continueRender(handle);
  })();
}, []);

// 매 프레임 명시적 렌더 — Remotion은 자동 루프 없음
useEffect(() => {
  if (!appRef.current || !ready) return;
  // 빗방울 위치 업데이트 (frame 기반 결정론적)
  (appRef.current.renderer as any).render(appRef.current.stage);
}, [frame, ready]);
```

## 8. render.mjs CLI 파라미터 전체 목록

### PuppetDialogueScene 전용

```bash
node render.mjs \
  --composition PuppetDialogueScene \
  --bgUrl        <URL>          # 배경 이미지 R2 URL
  --charAUrl     <URL>          # 캐릭터 A 누끼 PNG R2 URL

  --durationSec  8              # 오디오 길이 (초)

  --charAMouthYRatio 0.19       # A 입 Y 비율
  --charBMouthXRatio 0.50       # B 입 X 비율
  --charBMouthYRatio 0.21       # B 입 Y 비율
```

| 구현 상태 | 배경(RoomBackground) ✅ / 캐릭터 스타일 ⬜ |
| 구현 방법 | rembg 누끼 후 PIL로 흰 외곽선 추가 (stroke 3~5px) |

```python
# 화이트 스티커 외곽선 처리 (예시)
from PIL import Image, ImageFilter
import numpy as np

def add_white_stroke(img_rgba, stroke_px=4):
    alpha = img_rgba.split()[3]
    dilated = alpha.filter(ImageFilter.MaxFilter(stroke_px * 2 + 1))
    stroke = Image.new("RGBA", img_rgba.size, (255, 255, 255, 255))
    stroke.putalpha(dilated)
    result = Image.alpha_composite(stroke, img_rgba)
    return result
```
