# 3. 기술 및 코딩 표준 (Technical and Coding Standards)

## 코드 작성 및 컴포넌트 관리
* 파일명은 직관적(예: 'Landing Page.html')으로 짓고, 크게 수정할 경우 기존 버전을 보존하기 위해 새 이름으로 복사합니다.
* 1000줄 이상의 거대한 파일 작성을 피하고, 작은 JSX 파일 여러 개로 나눈 뒤 마지막에 메인 파일로 가져오도록 합니다.
* 여러 Babel 스크립트 파일 간에 컴포넌트를 공유하려면 파일 끝에서 `Object.assign(window, { ... })`을 통해 전역으로 내보내야 합니다.

## React 및 Babel 규칙
* 인라인 JSX가 포함된 React 프로토타입 작성 시, 제공된 버전과 무결성 해시가 포함된 정확한 스크립트 태그를 사용해야 합니다.
* **중요:** 전역 스타일 객체를 정의할 때 이름 충돌 방지를 위해 컴포넌트 이름을 딴 고유한 이름(예: `const terminalStyles = {}`)을 지어야 하며, 단순히 `const styles = {}`로 작성해서는 안 됩니다.

## 화면 참조 및 애니메이션
* 사용자가 특정 슬라이드를 지정할 수 있도록 1부터 시작하는 번호로 `[data-screen-label]` 속성을 부여해야 합니다(예: "01 Title").
* 인터랙티브 뷰에서 `scrollIntoView` 사용을 피하고 대체 DOM 스크롤 메서드를 사용하십시오.
* 슬라이드 덱에는 사용자의 명시적 요청이 없는 한 발표자 노트를 임의로 추가하지 마십시오.
* 데스크탑/모바일 프레임, 덱 캔버스 등은 직접 만들지 말고 `copy_starter_component`를 호출해 활용합니다.
고정 크기 콘텐츠는 자체 JS 스케일링을 구현해야 합니다.

## Tweaks UI 프로토콜
* Tweaks 패널을 만들 때는 `__activate_edit_mode` 이벤트 리스너를 **먼저** 등록한 뒤, 사용 가능함을 `postMessage`로 알립니다.
* 값이 변경되면 라이브로 적용함과 동시에 `__edit_mode_set_keys`를 보내 상태를 지속(Persisting)시켜야 합니다. 
이 상태는 루트 HTML 파일 내의 유효한 JSON 주석 블록 형태로 저장됩니다.
