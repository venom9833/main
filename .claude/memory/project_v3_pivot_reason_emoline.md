V2→V3 피봇의 핵심 동기 중 하나: **캐릭터 감정선 연결의 복잡성**.

V2의 잘못된 설계(브라우저 저장소 혼용, 모놀리식 page.tsx, 시리즈별 IndexedDB 저장) 위에서 캐릭터 감정선까지 연결하려니 부담이 극도로 커졌고, 이것이 V3 전환의 강한 동기가 됨.

**Why:** V2에서 감정선은 시리즈별 IndexedDB에 저장되어 영속성 없이 흩어지고, Gemini 주입 로직도 series_generate.py에 분산·혼재되었음. 기반 구조 자체가 복잡해서 감정선 같은 핵심 기능을 제대로 구현하기 어려웠음.

**How to apply:**
- V3 감정선은 `_emoline.json` 전역 영구 파일로 단순화 (시리즈 무관)
- V3 피봇 결정을 되돌리거나 V2 방식을 재도입하자는 제안에 이 맥락 환기
- V3 설계 결정 시 "V2에서 이미 복잡해서 안 됐던 것"을 참고 기준으로 사용
- 감정선 → 대본 프롬프트 주입은 V3에서 반드시 구현해야 할 핵심 기능으로 인식
