# 브런치 글쓰기 워크플로우 (Brunch Writing Workflow)

브런치 플랫폼에 최적화된 5단계 글쓰기 프로세스. 브런치 외 채널은 writing-workflow, 에세이는 essay-workflow, 장편(책)은 book-writing-workflow를 사용한다.

## 브런치 플랫폼 이해

스킬의 모든 단계는 아래 플랫폼 특성을 전제로 한다.

### 큐레이션 기반 플랫폼

브런치는 SEO 검색 유입이 아니라 **에디터 큐레이션과 독자 반응 기반**으로 글이 노출된다. 에디터가 선정한 글이 브런치 홈, 다음 포털 메인, 카카오톡 채널에 노출된다. 글의 품질과 주제 적합성이 노출의 핵심 조건이다.

### 에디터가 주목하는 요소

- 깊이 있는 통찰 — 표면 정보가 아닌 독자적 해석
- 독자 문제 해결 — 실질적 기준이나 판단 도구 제공
- 감성적 공감대 — 경험에서 우러나오는 보편적 정서
- 니치 전문성 — 특정 분야의 깊은 지식
- 시대적 흐름 반영 — 현재 독자가 관심을 가질 주제

### 독자 행동 패턴

- 제목을 보고 **0.3초** 만에 클릭 여부를 결정한다
- 도입부를 읽으며 **4.4초** 만에 계속 읽을지를 결정한다
- 글 읽기에 할애하는 최대 시간은 약 **3분** (공백 포함 2,000자 이내)
- 브런치 독자는 비계획 구매자 — 검색이 아니라 추천·노출로 유입된다

### 키워드 특성

브런치의 키워드는 SEO 키워드와 다르다. 검색 유입용이 아니라 에디터 큐레이션과 독자 반응의 기준점이다. 발행 시 키워드 3개를 선택하며, **독자가 반응하는 감정적 키워드**에 집중한다.

## 전체 흐름

```
Step 1: 주제·앵글 설계 → Step 2: 구조 설계 → Step 3: 초안 작성 → Step 4: 리라이팅 → Step 5: 발행 준비
```

사용자의 상태에 따라 적절한 단계부터 시작한다.
- 주제만 있음 → Step 1부터
- 앵글/구조 있음 → Step 3부터
- 초안 있음 → Step 4부터
- 다른 스킬에서 변환 (책 챕터 → 브런치 글 등) → Step 2부터

### Step 간 전환 규칙

각 Step 완료 후, 다음 Step으로 넘어가기 전에 사용자 확인을 받는다.

| 전환 | 확인 방식 |
|------|----------|
| Step 1 → 2 | 주제·앵글·독자·글 유형을 요약 제시하고, 확정 여부를 확인한 뒤 구조 설계로 진행한다 |
| Step 2 → 3 | 아웃라인과 제목 후보를 제시하고, 구조 수정이 필요한지 확인한 뒤 초안 작성으로 진행한다 |
| Step 3 → 4 | 초안을 제시하고, 방향 수정이나 추가 요청이 있는지 확인한 뒤 리라이팅으로 진행한다 |
| Step 4 → 5 | 수정본을 제시하고, 추가 수정이 필요한지 확인한 뒤 발행 준비로 진행한다 |

사용자가 "끝까지 진행해줘" 또는 "한 번에 해줘"라고 요청한 경우, 확인 없이 연속 진행한다.

## 공통 집필 원칙

### 문체 기준

- 표준어 사용
- 종결어미는 사용자 지정에 따름 (기본값: '~다'체 — 브런치의 주류 문체)
- 문장은 15~22단어 내외 기본 (브런치의 모바일 가독성 고려, 일반 글쓰기보다 짧게)
- **한 문장에는 하나의 정보, 하나의 판단만 담는다**
- 문장은 능동형을 기본으로 한다
- 문단은 2~4문장을 기본으로 한다 (브런치 모바일 화면에서 문단이 길면 읽기 부담)
- 줄바꿈은 문단 단위로만 적용. 소제목 전환, 장면 전환, 주제 블록 전환 시에만 허용
- 감정적 표현, 감탄형 문장 지양
- 전체 톤은 차분하고 개인적인 문체 유지

### 브런치 톤 가이드

브런치 글은 블로그의 정보 전달과 에세이의 개인 서사 사이에 위치한다. 아래 유형별로 톤을 조정한다.

| 글 유형 | 톤 | 특징 |
|---------|-----|------|
| 경험 기반 인사이트 | 관찰하는 실무자 | 경험에서 기준을 뽑아내는 방식. "나는 이렇게 했고, 이것이 기준이 되었다" |
| 전문 분야 해설 | 친근한 전문가 | 어려운 개념을 독자 눈높이로 풀어주되, 판단 기준을 명확히 제시 |
| 일상 관찰·성찰 | 담담한 이야기꾼 | 장면과 감각으로 시작해서 보편적 통찰로 연결 |
| 정보·가이드 | 구조적 안내자 | 조건 → 기준 → 결과 순서로 정리. 나열이 아닌 판단 기준 제공 |
| 시사·트렌드 분석 | 분석적 관찰자 | 현상 재정의 → 기준 제시 → 관점 전환 |

### 서술 전략

- 글의 첫 문장: **구체적 장면, 독자의 문제 상황, 또는 날카로운 질문**으로 시작. 정의나 개념 나열로 시작하지 않음
- 설명 순서: **상황 → 기준 → 적용 방식**
- 소제목은 기능명이 아닌 **판단·행동 중심 문장**으로 작성
- "가능하다"보다 **"이렇게 판단한다"** 식의 단정적 서술
- 마무리는 요약이 아니라 **관점의 재정렬** 또는 **독자에게 남기는 질문**

### 글쓰기 금지어 규칙

모든 문장은 **판단·기준·결과**가 드러나야 한다.

**① 과장형 형용사 금지**
금지어: 혁신적인, 획기적인, 창의적인, 강력한, 완벽한, 최고의, 탁월한, 뛰어난
→ 무엇이 어떻게 다른지, 수치·사례로 설명한다.

**② 모호한 부사 금지**
금지어: 매우, 굉장히, 상당히, 꽤, 쉽게, 빠르게, 간편하게, 효율적으로
→ 시간·단계·수치·조건으로 대체한다.

**③ 추측·완곡 표현 금지**
금지어: ~할 수 있습니다, ~일 수 있습니다, ~라고 볼 수 있습니다, 어느 정도, 부분적으로, 다소
→ 단정형으로 서술한다. 조건이 있다면 조건을 먼저 제시한다.
→ 단, 성찰적 불확실성("~일지도 모른다")은 일상 관찰·성찰 유형에서 허용한다.

**④ 불필요한 여유 연결어 금지**
금지어: 전반적으로 볼 때, 일반적으로 말하면, 어떤 면에서 보면, 이러한 측면에서, 결과적으로
→ 근거 → 주장 구조로 직접 연결한다.

**⑤ 추상 명사 중심 문장 지양**
주의어: 중요성, 필요성, 가능성, 효과, 가치, 측면, 부분
→ 동사 중심 문장으로 전환. 장면·행동·결과로 구체화한다.

**⑥ AI 흔적 조합 금지**
부사 + 형용사 + 가능성 표현 + 추상 명사 패턴은 금지한다.

### 금지 요소

- 정보 나열식 구성 (리스트만 던지고 해설 없는 글)
- 결과물에 대한 감상형 표현
- 과도한 반복 설명
- 근거 없는 과장·미사여구
- "오늘은 ~에 대해 이야기해 보겠습니다" 식의 메타 서술
- 제목에 넘버링(1화, 2화) 또는 날짜 사용

## 스킬 간 연계

### 이 스킬의 범위

이 스킬은 **브런치 플랫폼에 발행하는 단편 글**을 처리한다. 다음은 이 스킬의 범위 밖이다.
- 브런치 외 블로그·뉴스레터·보고서 → writing-workflow
- 에세이(수필·산문) → essay-workflow (단, 브런치에 발행하는 에세이는 이 스킬 사용)
- 장편(책) 집필 → book-writing-workflow
- 브런치북 기획 → 이 스킬의 Step 5에서 브런치북 연계 안내 후, 필요 시 book-writing-workflow로 전환

### 타 스킬 콘텐츠를 입력으로 받을 때

| 입력 | 처리 방식 |
|------|----------|
| 책 챕터 → 브런치 글로 축약 | 핵심 판단 기준 1~2개만 추출. 브런치 분량(1,200~2,000자)에 맞춰 재구성. 경험 중심 서술로 전환 |
| 강의 스크립트 → 브런치 글로 변환 | 구어체를 문어체로 전환. 시간 순서 → 논리 순서로 재배치. 도입부를 장면이나 질문으로 교체 |
| 일반 블로그 글 → 브런치 최적화 | 분량 조정(2,000자 이내), 제목 규칙 적용, 도입부 재설계, 소제목 행동·판단 중심으로 전환 |

## Step 1: 주제·앵글 설계 (Topic & Angle Design)

글을 쓰기 전에 다음 5가지를 명확히 한다.

### 수집 항목

| 항목 | 질문 | 예시 |
|------|------|------|
| **주제** | 무엇에 대해 쓰는가? | AI 글쓰기, 건설안전교육, 직장 경험 |
| **앵글** | 이 주제를 어떤 시선으로 보는가? 독자가 몰랐던 것은? | "AI가 글을 쓰는 게 아니라, 사고를 정렬하는 도구다" |
| **독자** | 누가 읽는가? 현재 수준은? | 입문자, 실무자, 같은 경험을 한 사람 |
| **글 유형** | 어떤 형식인가? | 경험 기반 인사이트 / 전문 해설 / 일상 성찰 / 가이드 / 트렌드 분석 |
| **매거진** | 기존 매거진에 포함되는가? 새 매거진인가? | 매거진명, 연재 순서 (선택) |

### 앵글 설계 기준

브런치에서 반응을 얻는 글은 정보 전달이 아니라 **시선의 전환**을 제공한다. 앵글을 잡을 때 다음을 점검한다.

- **"그래서 뭐?"를 넘기는가** — 정보만 전달하면 검색 결과와 다를 바 없다. 독자가 생각의 기준을 바꾸게 하는 관점이 있는가.
- **나만 할 수 있는 이야기인가** — 직접 경험, 특정 분야의 깊은 지식, 독자적 해석이 포함되어야 한다.
- **지금 읽어야 하는 이유가 있는가** — 시의성, 독자의 현재 고민과의 접점.

### 산출물

5가지 항목을 요약 정리해 사용자에게 제시한다. 사용자 확인 후 Step 2로 진행한다.

## Step 2: 구조 설계 (Structure Design)

### 브런치 글 구조 패턴

글 유형에 따라 아래 구조를 기본으로 하되, 사용자의 의도에 맞게 조정한다.

**경험 기반 인사이트:**
```
도입: 구체적 장면 또는 상황 제시 (독자가 공감할 수 있는 경험)
전개 1: 그 경험에서 발견한 문제 또는 오해
전개 2: 기준의 재정의 — 왜 다르게 봐야 하는가
마무리: 관점 전환 — 독자가 가져갈 질문 또는 기준
```

**전문 분야 해설:**
```
도입: 독자의 문제 상황 또는 질문 (검색하게 만드는 그 질문)
본론 1: 핵심 개념과 판단 기준
본론 2: 실제 적용 방식 + 예시
마무리: 독자의 다음 행동 또는 기준 정리
```

**일상 관찰·성찰:**
```
도입: 감각적 장면 (시각, 청각, 촉각 등으로 시작)
전개: 장면에서 관찰한 것 → 떠오른 생각 → 기존 생각과의 차이
마무리: 여운 — 독자에게 남기는 질문 또는 되돌아가는 장면
```

**정보·가이드:**
```
도입: 이 정보가 필요한 구체적 상황
본론: 조건 → 기준 → 결과 순서로 정리 (나열이 아닌 판단 흐름)
마무리: 핵심 기준 요약 + 다음 행동
```

### 제목 설계

브런치 제목은 글의 첫 번째 관문이다. 아래 규칙을 적용한다.

**제목 규칙:**
- 전체 20자 이내 (브런치 허용 상한)
- **핵심 정보는 앞 10자 이내에 배치** (모바일 미리보기에서 잘리는 지점)
- 넘버링(1화, 2화) 금지 — 포털 메인 노출 제한
- 날짜 금지
- 글 내용 중 인상적인 문장을 제목으로 활용 가능

**제목 유형:**
| 유형 | 예시 | 적합한 글 |
|------|------|----------|
| 질문형 | "그 도구, 정말 써야 할까" | 기존 관념에 의문을 제기하는 글 |
| 상황 제시형 | "퇴사 후 첫 월요일" | 경험 기반, 공감 유도 |
| 기준 제시형 | "좋은 글의 조건은 하나다" | 전문 해설, 인사이트 |
| 반전형 | "열심히 한 사람이 지는 이유" | 통념을 뒤집는 글 |
| 감각형 | "커피가 식는 동안" | 일상 성찰, 에세이 |

제목 후보를 **5개** 생성한다. 부제(서브타이틀)도 함께 제시한다.

### 산출물

아웃라인 + 제목 후보 5개 + 부제를 사용자에게 제시한다. 사용자 확인 후 Step 3으로 진행한다.

---

## Step 3: 초안 작성 (First Draft)

### 초안 작성 규칙

- Step 2에서 확정된 구조를 따라 작성한다
- 공통 집필 원칙(서술 전략, 문체 기준, 금지어 규칙)을 적용한다
- **도입부 3문장에 특별히 집중한다** — 브런치 미리보기에 노출되는 구간
- 분량: 공백 포함 **1,200~2,000자** (3분 읽기 기준)
- 문단은 2~4문장 이내 유지 (모바일 가독성)
- 소제목은 2~3개 이내 사용. 글이 짧으면(1,500자 이하) 소제목 없이 구분선으로 처리
- 이미지 삽입 위치 표시: `[IMAGE: 설명]` — 글과 직접 관련된 이미지만

### 도입부 설계 (4.4초 규칙)

독자는 도입부를 4.4초 안에 판단한다. 다음 중 하나의 방식으로 시작한다.

| 방식 | 예시 | 효과 |
|------|------|------|
| 장면 시작 | "회의실 불이 꺼지고, 프로젝터만 켜져 있었다." | 호기심, 몰입 |
| 문제 직면 | "세 번째 수정 요청을 받았을 때, 문제는 글이 아니었다." | 공감, 긴장 |
| 질문 던지기 | "왜 매번 같은 방식으로 실패하는 걸까." | 사고 자극 |
| 반직관 선언 | "좋은 글은 잘 쓴 글이 아니다." | 반전, 호기심 |

**금지되는 도입:**
- "오늘은 ~에 대해 이야기하겠습니다"
- "~란 무엇인가? ~는 ~를 의미한다" (사전식 정의)
- "최근 ~가 화제입니다" (뉴스 리드식)

### 산출물

- 초안은 **대화창 텍스트로 직접 제공**한다 (파일 생성하지 않음)
- 사용자가 파일을 명시적으로 요청한 경우에만 `draft.md`로 저장한다
- 사용자 확인 후 Step 4로 진행한다

## Step 4: 리라이팅 (Rewriting)

초안을 5가지 관점에서 점검하고 수정한다.

### 진행 방식

1. **점검 리포트 제시** — 5가지 점검 결과를 표 형태로 사용자에게 보여준다
2. **사용자 확인** — 수정 방향에 대해 동의 또는 추가 지시를 받는다
3. **수정본 작성** — 확인된 방향에 따라 전체 수정본을 제시한다
4. **변경 요약** — 수정본 하단에 주요 변경 사항을 간결하게 정리한다

사용자가 "리라이팅해줘"라고만 요청한 경우, 1~4를 한 번에 진행한다.

### 점검 1: 도입부 점검 (4.4초 규칙)

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 첫 문장이 장면·문제·질문·반직관 중 하나로 시작하는가 | 정의·나열·메타 서술로 시작했다면 교체 |
| 2 | 첫 3문장 안에 독자가 계속 읽을 이유가 있는가 | 호기심·공감·긴장 중 하나가 작동하는지 확인 |
| 3 | 브런치 미리보기에서 잘렸을 때도 매력적인가 | 첫 2문장만 보이는 상태를 가정하고 점검 |

### 점검 2: 구조 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 전체 흐름이 상황 → 기준 → 적용 순서를 따르는가 | 순서 재배치 |
| 2 | 소제목이 행동·판단 중심 문장인가 | 기능명·명사 나열형이면 전환 |
| 3 | 마무리가 요약이 아닌 관점 재정렬 또는 여운으로 끝나는가 | 요약형 마무리를 질문 또는 장면 회귀로 전환 |

### 점검 3: 문장·금지어 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | "~할 수 있습니다"가 있는가 | 단정형 전환 |
| 2 | "매우, 쉽게, 빠르게"가 있는가 | 수치·조건·단계로 대체 |
| 3 | 과장형 형용사가 근거 없이 쓰였는가 | 비교 기준 또는 수치로 교체 |
| 4 | 추상 명사가 문장 중심에 있는가 | 동사 중심 문장으로 전환 |
| 5 | 문장이 15~22단어 범위 내인가 | 초과 시 분리 |
| 6 | AI 흔적 조합(부사+형용사+가능성+추상명사)이 있는가 | 해체 후 재구성 |

### 점검 4: 스타일 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 방법·팁이 기준 설명 없이 먼저 등장하지 않는가 | 기준 문단 추가 |
| 2 | 감정적 공감이 논리 설명보다 앞서지 않는가 | 상황 진단형으로 교체 |
| 3 | 문체 리듬이 점층 구조를 따르는가 | 관찰 → 판단 순서로 조정 |

### 점검 5: 브런치 최적화 점검

| # | 점검 항목 | 수정 방향 |
|---|----------|----------|
| 1 | 분량이 1,200~2,000자 범위 내인가 | ±20% 이내로 조정 |
| 2 | 문단이 모바일에서 읽기 편한 길이인가 (2~4문장) | 긴 문단 분리 |
| 3 | 글과 무관한 장식용 이미지가 없는가 | 제거 또는 교체 |
| 4 | 제목이 20자 이내이며 앞 10자에 핵심이 있는가 | 제목 재설계 |
| 5 | 톤이 글 유형에 적합한가 | 톤 가이드와 대조 |

### 변경 요약 표준 포맷

```
**주요 변경 사항:**
- 도입부: (변경 내용)
- 구조: (변경 내용)
- 문장: (변경 내용)
- 스타일: (변경 내용)
- 브런치 최적화: (변경 내용)
```

## Step 5: 발행 준비 (Publish Ready)

Step 4 수정본을 브런치 발행 수준으로 마무리한다.

### 진행 방식

1. **최종 점검 실행** — 아래 항목을 점검하고 결과를 사용자에게 제시한다
2. **제목·부제 확정** — 후보를 제시하고 사용자가 선택한다
3. **발행 메타 정보 작성** — 키워드, 커버 이미지 방향 제안
4. **사용자 확인** — 최종본을 보여주고 확정 여부를 확인한다
5. **파일 생성** — 확정 후 파일을 생성한다

### 최종 점검 항목

| # | 점검 항목 | 기준 |
|---|----------|------|
| 1 | 제목 확정 | 후보 5개 중 선택 또는 새로 생성. 20자 이내, 앞 10자 핵심 |
| 2 | 부제 확정 | 제목을 보충하는 1문장. 브런치 부제 영역에 표시됨 |
| 3 | 맞춤법·문법 교정 | 한국어 맞춤법, 띄어쓰기, 외래어 표기법, 문장부호 |
| 4 | 키워드 3개 선정 | 브런치 발행 시 선택하는 키워드. 감정적·주제적 키워드 조합 |
| 5 | 커버 이미지 방향 | 글의 톤에 맞는 이미지 방향 제안 (직접 생성하지 않음) |
| 6 | 분량 최종 확인 | 1,200~2,000자 범위(±20%) |
| 7 | [TODO] 마커 해결 | 모든 `[TODO]` 마커 해결 또는 제거 |

### 매거진·브런치북 연계 안내

- 매거진에 포함되는 글이면, 매거진 내 위치와 이전/이후 글과의 연결을 확인한다
- 브런치북으로 묶을 계획이 있으면, 글 간 흐름·주제 일관성을 점검하고 book-writing-workflow 전환을 안내한다

### 산출물

| 파일 | 설명 |
|------|------|
| `brunch-final.md` | 최종 완성본 (브런치 에디터에 복사·붙여넣기용) |
| `brunch-final.docx` | 최종 완성본 (문서 보관용, 요청 시) |

출력 포맷은 사용자 지정에 따름. 기본값은 `.md` (브런치 에디터 호환성).
`.docx` 생성 시 반드시 `/mnt/skills/public/docx/SKILL.md`를 읽고 따른다.

최종본과 함께 아래 **발행 체크리스트**를 제시한다.

```
**브런치 발행 체크리스트:**
□ 제목 (20자 이내, 앞 10자 핵심)
□ 부제
□ 키워드 3개: _____, _____, _____
□ 커버 이미지
□ 매거진 선택 (해당 시)
□ 발행
```

## 분량 통제 규칙

수정·보강·추가 요청 시 원본 분량이 의도 없이 늘어나는 것을 방지한다.

- **"다듬어줘" / "수정해줘"** = 원본의 문장 수·문단 수·전체 구조를 유지한 채 표현만 정리. 새 문장·문단 추가 금지
- **"보강해줘"** = 지정된 부분에 한해 내용 추가 허용. 미지정 부분은 원본 유지
- **"추가해줘"** = 지정된 위치에 지정된 분량만 삽입
- 수정 결과물이 2,000자를 초과하면, 초과 사유를 사용자에게 먼저 확인
