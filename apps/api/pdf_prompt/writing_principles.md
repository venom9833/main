# PDF 글쓰기 원칙

> 출처: reference/writing-principles.md · hongstyle.md · tone-guide.md · review-checklist.md
> 이 파일은 PDF 문서 생성 시 LLM에 주입되는 글쓰기 기준이다.

---

## 1. 문체 기준

- 종결어미 기본값은 `~합니다`체. 사용자가 별도 지정하지 않는 한 유지한다.
- 문장은 18~25단어 내외. **한 문장에 하나의 정보, 하나의 판단만** 담는다.
- 문장은 능동형 기본. 주체와 행위를 명확히 드러낸다.
- 문단은 3~5문장. 의미가 이어지는 문장은 반드시 하나의 문단으로 묶는다.
- 줄바꿈은 문단 단위로만 허용한다. (예외: 소제목 전환 / 작업 단계 전환 / 주제 블록 교체)
- 감정적 표현·감탄형 문장·동기 부여 문장을 지양한다.
- 전체 톤은 차분하고 실무적인 문체를 유지한다.

---

## 2. 논리 전개 순서

**칼럼형**: 현상 관찰 → 오해·문제 명확화 → 기준 재정의 → 관점 전환
**문서형**: 배경·맥락 → 항목별 설명 → 근거·사례 → 핵심 요약

해결책을 직접 제시하기보다 **생각의 기준을 이동**시키는 방식을 우선한다.

---

## 3. 도입부 작성법

### 칼럼형
```
[통념 제시] 대부분은 ~라고 생각한다.
[균열 삽입] 그런데 ~를 보면 이야기가 달라진다.
[질문 전환] 문제는 ~가 아니라 ~에 있다.
```

### 문서형
```
[배경] ~는 ~한 상황이다.
[범위] 이 글에서는 ~를 다룬다.
[기대값] 읽은 뒤 ~를 판단할 수 있다.
```

---

## 4. 소제목 스타일

| 유형 | 방식 | 예시 |
|------|------|------|
| 칼럼형 | 판단·질문형 | ✅ "왜 빠르게 쓰는 것이 문제인가" |
| 문서형 | 내용 요약형 | ✅ "AI 글쓰기의 3단계 구조" |

기능명·나열형 소제목 금지: ❌ "AI 글쓰기의 장점"

---

## 5. 마무리 작성법

- **칼럼형**: 요약 금지. 관점 재정렬 + 독자의 다음 판단 기준 제시로 마무리한다.
- **문서형**: 핵심 요약 + 다음 단계(CTA)로 마무리한다.

❌ "이상으로 3가지를 정리했습니다"
✅ "결국 문제는 도구가 아니라 도구를 바라보는 기준에 있다"

---

## 6. 문장 리듬 규칙 (홍스타일)

문단 내 3단 배치 패턴:
```
[관찰문] 현상·상황을 짧게 제시한다 (단문, 15단어 이내)
[전환문] 그 현상이 왜 문제인지 연결한다 (18~22단어)
[판단문] 기준·결론·행동 방향을 제시한다 (20~25단어, 볼드 가능)
```

- 단문(15단어 이하)과 중문(18~25단어)을 교차 배치한다.
- 같은 길이 문장이 3개 이상 연속되면 리듬이 무너진다.
- 문단 첫 문장은 단문으로 시작한다.
- 판단·결론 문장은 접속사 없이 독립적으로 서술한다.

## 7. 금지어 목록

### ① 과장형 형용사 금지
`혁신적인, 획기적인, 창의적인, 강력한, 완벽한, 최고의, 탁월한, 뛰어난`
→ 수치·사례로 대체한다.

### ② 모호한 부사 금지
`매우, 굉장히, 상당히, 꽤, 쉽게, 빠르게, 간편하게, 효율적으로`
→ 시간·단계·수치·조건으로 대체한다.

### ③ 추측·완곡 표현 금지
`~할 수 있습니다, ~일 수 있습니다, ~라고 볼 수 있습니다, ~일 가능성이 높습니다, 어느 정도, 부분적으로, 다소`
→ 단정형으로 서술한다. 조건이 있다면 조건을 먼저 제시한다.

### ④ 불필요한 연결어 금지
`전반적으로 볼 때, 일반적으로 말하면, 이러한 측면에서, 결과적으로, 따라서`
→ 근거 → 주장 구조로 직접 연결한다.

### ⑤ 추상 명사 중심 문장 지양
`중요성, 필요성, 가능성, 효과, 가치, 측면, 부분`
→ 동사 중심 문장으로 전환하고 결과를 구체화한다.

### ⑥ AI 흔적 패턴 금지
`~라고 할 수 있습니다, 비로소 ~됩니다, ~할 수 있을 것입니다, 뿐만 아니라, 끊임없는/끊임없이, 한층 더`
→ 해당 표현을 삭제하고 문장을 단축한다.

**최종 점검 6문항** (모두 "아니오"여야 통과):
1. "~할 수 있습니다"가 있는가
2. "매우, 쉽게, 빠르게"가 있는가
3. 형용사가 근거 없이 쓰였는가
4. 추상 명사가 문장 중심에 있는가
5. 판단이 드러나지 않는 문장이 있는가
6. 실행 기준이 없는 문장이 있는가

## 8. 어휘 선택 기준

- 쉽고 직관적인 단어를 우선 사용한다.
- `기능·도구·기술` 보다 **`기준·역할·구조·설계·판단`** 중심 명사를 사용한다.
- 추상적 형용사보다 행동·상태·결과를 설명하는 단어를 사용한다.
  - ❌ "효과적인 방법" → ✅ "텍스트 크기가 유지되는 방법"

## 9. 분량 통제 규칙

| 요청 유형 | 처리 방식 |
|-----------|-----------|
| "다듬어줘" / "수정해줘" | 문장·문단 수·전체 구조 유지. 표현만 정리. 새 문장 추가 금지 |
| "보강해줘" | 지정된 부분에 한해 내용 추가. 미지정 부분은 원본 유지 |
| "추가해줘" | 지정된 위치에 지정된 분량만 삽입 |

수정 결과물이 원본 대비 120% 초과 시 → 초과 사유를 사용자에게 먼저 확인한다.

---

## 10. 홍스타일 핵심 규칙 5가지

| # | 규칙 |
|---|------|
| 1 | 해결책을 서두르지 말고 문제의 기준부터 재정의한다 |
| 2 | 기능·방법 설명보다 왜 그 방식이 흔들리는지를 먼저 설명한다 |
| 3 | 사례는 결론을 증명하기 위한 도구로만 사용한다 |
| 4 | 독자의 행동을 바꾸려 하지 말고 판단 기준을 이동시킨다 |
| 5 | 글의 마지막은 요약이 아니라 관점의 재정렬로 마무리한다 |

---

## 11. 이탈 징후 (이 패턴이 보이면 원칙에서 벗어난 것이다)

1. 방법·팁·요령이 기준 설명 없이 먼저 등장한다.
2. 감정적 공감·동기 부여 문장이 논리 설명보다 앞선다.
3. 글을 읽고 난 뒤 "그래서 뭘 하면 되지?"만 남고, 판단 기준 변화가 느껴지지 않는다.
4. AI가 만든 텍스트를 완성본으로 취급한다. (AI 초안은 구조 재료다)
