# Watchdog — Script Rule 중복·충돌 감시자
> **이 파일의 목적**: `apps/api/prompts/` 내 모든 프롬프트 파일의 규칙을 단일 소스로 추적한다.
> 프롬프트 파일을 수정하기 전 반드시 이 파일을 열어 중복·충돌 여부를 확인한다.
> 수정 후에는 이 파일도 함께 갱신한다.

## 3. 규칙 단일 소스 (Single Source of Truth)

규칙이 여러 파일에 있을 때 **어느 파일이 권위(master)인지** 명시한다.
수정 시 Master 파일만 수정하고, 나머지는 Master를 참조하도록 표현을 유지한다.

| 규칙 | Master 파일 | 종속 파일 (Master 따름) |
|------|------------|----------------------|
| 문체 6원칙 (감정·대사·비밀·공간·훅·리듬) | `wiki_query.md` | `wiki_lint.md`, `reviser.md` |
| 대사 비율 | `wiki_query.md` (30% 이하) | — |
| 시리즈 감정 아크 (설렘→긴장→충격→여운) | `architect.md` | `wiki_lint.md` 차원 18 |
| 복선 타이밍 (1~3화 심기 / 4~6화 회수) | `architect.md` | `wiki_lint.md` 차원 32 |

## 5. 수정 전 체크리스트

프롬프트 파일을 **추가·수정·삭제**하기 전 반드시 아래를 확인한다.

```
[ ] 1. 변경하려는 규칙이 이미 다른 파일에 있는가? (2번 표 확인)
[ ] 2. 해당 규칙의 Master 파일이 어느 것인가? (3번 표 확인)
[ ] 3. 수치/값이 있는 규칙인가? (대사 비율, 글자 수, 챕터 수 등)
       → 있다면: 모든 파일에서 동일한 값인가?
[ ] 4. 새 규칙을 추가한다면: 기존 규칙과 모순되는가?
[ ] 5. 수정 완료 후: 이 파일(watchdog-scriptrule.md)에 변경 사항을 반영했는가?
[ ] 6. 수정 완료 후: 4번(해소된 충돌 이력)에 기록했는가?
```

## 7. 의도적 중복 허용 기준

lint가 생성 규칙을 **동일하게** 검수하는 것은 설계상 정상이다.
단, 아래 조건을 만족해야 한다:

1. **표현 불일치 허용** — lint는 "위반 여부 확인" 관점, 생성은 "준수 지시" 관점으로 다르게 표현 가능
2. **값 불일치 금지** — 수치(비율, 횟수, 자 수)는 반드시 동일해야 함
3. **reviser는 생성 규칙의 부분 집합** — reviser.md가 새 규칙을 독자적으로 정의하면 Master 파일에도 반영할 것
