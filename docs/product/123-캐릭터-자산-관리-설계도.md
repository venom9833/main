# 123 — 캐릭터 자산 관리 시스템 설계도

> 최초 작성: 2026-03-29
> 상태: 설계 확정 / 구현 대기 (현재 IndexedDB 임시 운영 중)

---

## 1. 개요

캐릭터는 **팀원 1명 — 1개 영상제작구조 — 1개 화풍**에 종속되는 핵심 자산이다.
캐릭터 등록 목적은 씬 이미지 생성(키프레임) 및 AI 영상 생성(MP4 프롬프트) 시
캐릭터 외형 묘사를 **일관되게 재현**하기 위한 프롬프트를 보관하는 것이다.

### 현재 상태 (임시)
- 저장소: `IndexedDB (ld_characters)`
- 권한 제어: 없음 (로컬 브라우저만 접근)
- 팀 공유: 불가

### 목표 상태 (구현 대기)
- 저장소: Supabase `characters` 테이블 + Supabase Storage (이미지)
- 권한 제어: 등록자 본인 + 관리자만 삭제 가능
- 팀 공유: 전 팀원 조회 가능, 등록/삭제는 본인 한정

## 2. 캐릭터 데이터 구조

### 2-1. 핵심 필드

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | UUID | 고유 식별자 |
| `name` | TEXT | 캐릭터 이름 (예: 건강박사 김선생) |
| `image_url` | TEXT | Supabase Storage URL |
| `prompt_en` | TEXT | 캐릭터 외형 묘사 영문 프롬프트 (상세 구조화 문장) |
| `registered_by` | TEXT | 등록자 session_key (localStorage `ld_session_key`) |
| `registered_at` | TIMESTAMPTZ | 등록 일시 |
| `style_tag` | TEXT | 화풍 태그 (예: ghibli, pixar-3d, flat-2d) — nullable |
| `is_public` | BOOLEAN | 팀 전체 공개 여부 (기본 true) |

### 2-2. IndexedDB 현재 구조 (임시)

```typescript
interface RegisteredCharacter {
  id: string;           // crypto.randomUUID()
  name: string;
  imageDataUrl: string; // base64 (임시 — Supabase 전환 시 image_url로 교체)
  promptEn: string;
  registeredAt: string; // ISO string
}
```

> ⚠️ `imageDataUrl` (base64)는 IndexedDB 전용 임시 필드.
> Supabase 전환 시 Supabase Storage URL로 마이그레이션 필요.

## 3. Supabase 스키마 (구현 시 적용)

```sql
-- characters 테이블
CREATE TABLE public.characters (
  id             UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  name           TEXT        NOT NULL,
  image_url      TEXT        NOT NULL,
  prompt_en      TEXT        NOT NULL,
  registered_by  TEXT        NOT NULL,   -- ld_session_key
  registered_at  TIMESTAMPTZ DEFAULT now(),
  style_tag      TEXT,
  is_public      BOOLEAN     DEFAULT true
);

-- RLS 활성화
ALTER TABLE public.characters ENABLE ROW LEVEL SECURITY;

-- 조회: 전체 공개 캐릭터는 누구나
CREATE POLICY "characters_select_public"
  ON public.characters FOR SELECT
  USING (is_public = true);

-- 삽입: session_key 보유자
CREATE POLICY "characters_insert"
  ON public.characters FOR INSERT
  WITH CHECK (registered_by IS NOT NULL AND length(registered_by) > 0);

-- 삭제: 등록자 본인만 (관리자는 서버 서비스 롤 키로 우회)
CREATE POLICY "characters_delete_owner"
  ON public.characters FOR DELETE
  USING (registered_by = current_setting('request.headers')::json->>'x-session-key');
```

### Supabase Storage 버킷

```
버킷명: character-images
접근: public (URL로 직접 조회 가능)
파일 경로: characters/{session_key}/{character_id}.{ext}
허용 타입: image/jpeg, image/png, image/webp
최대 크기: 5MB
```

## 4. API 라우트 설계 (Next.js App Router)

### 4-1. `GET /api/characters`
- 전체 공개 캐릭터 목록 반환
- 정렬: `registered_at DESC`

### 4-2. `POST /api/characters`
- 요청 헤더: `x-session-key: {session_key}`
- 요청 바디: `{ name, imageFile(base64), promptEn, styleTag }`
- 처리:
  1. Supabase Storage에 이미지 업로드 → `image_url` 획득
  2. `characters` 테이블에 INSERT

### 4-3. `DELETE /api/characters/[id]`
- 요청 헤더: `x-session-key: {session_key}` 또는 `x-admin-token: {token}`
- 권한 확인:
  - 본인: DB에서 `registered_by === session_key` 검증
  - 관리자: `x-admin-token === process.env.ADMIN_DELETE_TOKEN` 검증
- 처리:
  1. Storage에서 이미지 삭제
  2. `characters` 테이블에서 DELETE

## 5. 관리자 권한 설계

### 관리자 식별 방식: **Option A — 환경변수 토큰**

```
ADMIN_DELETE_TOKEN=링크드랍_관리자_전용_시크릿_키
```

- 관리자 브라우저: `localStorage`에 `ld_admin_token` 저장
- 삭제 요청 시 API가 서버 측 `ADMIN_DELETE_TOKEN`과 비교 검증
- GNB 설정 모달에 "관리자 토큰" 입력란 추가 예정

### 관리자 권한 범위
| 작업 | 등록자 | 관리자 |
|------|--------|--------|
| 캐릭터 조회 | ✅ | ✅ |
| 캐릭터 등록 | ✅ | ✅ |
| 본인 캐릭터 삭제 | ✅ | ✅ |
| 타인 캐릭터 삭제 | ❌ | ✅ |

## 6. 프론트엔드 전환 계획

### 6-1. session_key 초기화
```typescript
// 앱 최초 로드 시 (layout.tsx 또는 providers.tsx)
if (!localStorage.getItem('ld_session_key')) {
  localStorage.setItem('ld_session_key', crypto.randomUUID());
}
```

### 6-2. characterimage 페이지 변경 사항
- `openCharIDB / loadRegisteredChars / saveRegisteredChar / deleteRegisteredChar` 제거
- API 호출로 교체: `fetch('/api/characters', ...)`
- 이미지: base64 → File 객체로 서버 전송 후 Storage URL 수신
- 삭제 버튼: `registered_by === 내 session_key` 또는 `ld_admin_token` 보유 시만 표시

### 6-3. 다른 페이지 연동 (현재 IndexedDB → 추후 API)
| 페이지 | 연동 방식 | 상태 |
|--------|----------|------|
| `/content/characterimage` | 등록/조회/삭제 | IndexedDB 임시 운영 |
| `/content/keyframe` | 씬 이미지 생성 시 캐릭터 프롬프트 자동 삽입 | 미구현 |
| `/content/mp4-prompt-generator` | charInput에 캐릭터 선택 UI | 미구현 |

## 8. 이 시스템과 시리즈 대본 캐릭터 시스템의 구분

LinkDrop에는 "캐릭터"라는 이름을 쓰는 시스템이 **두 개** 존재한다. 혼동하지 말 것.

| 구분 | 이 문서 (123) | 시리즈 대본 캐릭터 (125) |
|------|--------------|------------------------|
| 목적 | 씬 이미지·MP4 생성 시 외형 일관성 | 웹소설 대본 생성 시 성격·심리 일관성 |
| 핵심 데이터 | 외형 묘사 영문 프롬프트 (`prompt_en`) | `public_face` / `shadow` / `lie_to_self` 등 |
| 저장 위치 | IndexedDB → Supabase `characters` 테이블 | `apps/web/src/data/characters/{id}.json` |
| 사용 위치 | `/content/keyframe`, `/content/mp4-prompt-generator` | `/series/world`, `/series/script` |
| Gemini 활용 | 이미지 생성 프롬프트로 전달 | 대본 생성 프롬프트로 전달 |
| 캐릭터 수 | 팀원이 등록하는 수 (제한 없음) | 사전 정의된 22개 고정 캐릭터 풀 |

**핵심 차이**: 123 시스템의 캐릭터는 **어떻게 생겼는가** (외형), 125 시스템의 캐릭터는 **어떤 사람인가** (내면)를 다룬다.
