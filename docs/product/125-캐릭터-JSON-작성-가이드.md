# 125 — 캐릭터 JSON 작성 가이드

> 목적: 각 캐릭터 파일은 **겉으로 보이는 모습**과 **절대 들키고 싶지 않은 속모습**을 분리해서 담는다.
> 이 간격이 클수록 드라마가 깊어진다.
> 파일 위치: `apps/web/src/data/characters/{id}.json`

---

## 1. 이 파일이 존재하는 이유

사람은 두 개의 얼굴을 가지고 산다.

- **겉모습** — 직장·가족·이웃에게 보여주는 사회적 페르소나
- **속모습** — 혼자 있을 때의 진짜 자신. 부끄럽고 찌질하고 들키고 싶지 않은 것

웹소설이 재미있는 이유는 이 간격이 드러나는 순간 때문이다.
캐릭터 파일은 그 두 얼굴을 **따로** 기록하기 위해 존재한다.

---

## 2. 전체 구조

```json
{
  "id": "park_jh",
  "name": "박준혁",
  "gender": "male",
  "age": 44,
  "occupation": "IT 중견기업 차장",

  "core": {
    "public_face":       "남들에게 보이는 모습 — 사회적 페르소나",
    "shadow":            "절대 들키고 싶지 않은 진짜 속모습, shadow를 잘 쓰는 기준: 이걸 SNS에 올리면 욕먹을 것 같다는 느낌이 들어야 한다. 그 수위가 독자가 '어, 이거 나 같은데?'라고 느끼는 수위다.",
    "lie_to_self":       "이 간격을 유지하려고 자신에게 하는 거짓말",
    "fear":              "shadow가 들켰을 때 일어나는 일",
    "under_stress":      "극한 상황에서 shadow가 새어나오는 방식",
    "speaking_style":    "말투와 대화 습관",
    "speaking_examples": ["실제 대사 예시 2~4개"]
  },

  "situations": [
    "이번 시리즈에서 선택할 출발 상황"
  ],

  "relationships": {
    "상대방 이름": "이 인물이 상대를 보는 시선 (겉과 속이 달라도 됨)"
  }
}
```

---

## 3. 핵심 — 4개 필드의 관계

```
public_face  ←────────────────→  shadow
  (남들이 보는 나)          (진짜 나)
        ↑                        ↑
   lie_to_self             under_stress
  (간격을 유지하는 거짓말)   (위기 때 shadow가 새는 방식)
        ↓
      fear
  (간격이 무너질 때 생기는 공포)
```

**이 4개가 맞물려야 Gemini가 입체적인 장면을 쓴다.**
필드 하나가 비어 있으면 그 캐릭터는 평면이 된다.

---

## 4. `public_face` 작성법

남들에게 어떤 사람으로 보이는지. 본인이 의도적으로 만들어온 이미지.

**나쁜 예 — 실제 성격을 씀:**
```
"public_face": "불안하고 소심한 사람"
```

**좋은 예 — 남들이 보는 이미지를 씀:**
```
"public_face": "무난하고 성실한 가장. 직장에서 '무해한 사람'으로 통한다. 가족에게는 항상 괜찮다고 말한다. 웃음이 많다."
```

---

## 5. `shadow` 작성법 ← 가장 중요

이 파일을 따로 만든 진짜 이유다.
찌질하고 부끄럽고 인간적인 것을 숨기지 말고 써야 한다.

**나쁜 예 — 너무 점잖게 씀:**
```
"shadow": "사실 경제적으로 힘든 상황이다"
```

**좋은 예 — 들키고 싶지 않은 것을 날것으로 씀:**
```
"shadow": "2년째 아내와 잠자리가 없다. 이유를 모른다고 하지만 안다. 밤에 혼자 술을 마시며 다른 여자를 생각한다. 회사 구조조정 명단에 자기 이름이 있는 걸 몰래 봤는데 아무한테도 말 못 하고 있다. 아이가 '아빠는 왜 맨날 걱정해?'라고 물었을 때 '안 그래'라고 웃으며 대답했다. 그날 밤 화장실에서 울었다."
```

`shadow`에 들어갈 수 있는 것들:
- 부끄러운 욕망 (돈, 성, 탈출 등)
- 감추고 있는 실수나 범죄
- 남들이 알면 실망할 행동
- 본인도 인정하기 싫은 감정 (질투, 안도, 혐오)
- 매일 하는 소소한 거짓말

---

## 6. `lie_to_self` 작성법

`public_face`와 `shadow` 사이의 간격을 어떻게 정당화하는지.
이게 있어야 캐릭터가 '나쁜 사람'이 아니라 '인간'이 된다.

**공식:**
```
[자신이 믿고 싶은 것] — [하지만 실제 진실]. [이 자기기만의 이름]
```

**예시:**
```
"lie_to_self": "나는 다 잘 되고 있어, 곧 나아질 거야 — 사실 포기 직전이다. '낙관'이라는 이름의 회피"

"lie_to_self": "한 번만이야, 다시는 안 해 — 이미 열세 번째 '한 번만'이다"

"lie_to_self": "가족을 위해서 하는 거야 — 사실 자신이 무서워서 도망 못 가는 거다"
```

---

## 7. `fear` 작성법

shadow가 노출됐을 때 어떤 일이 벌어지는가.

**나쁜 예 — 추상적:**
```
"fear": "남들에게 나쁘게 보이는 것"
```

**좋은 예 — 구체적 장면으로:**
```
"fear": "아내가 통장 내역을 보는 것. 아이가 다 크고 나서 '아빠는 그때 왜 그랬어?'라고 묻는 것. 직장 동료들이 자신이 구조조정 대상인 걸 알고 이미 다른 눈으로 보고 있다는 것."
```

---

## 8. `under_stress` 작성법

극한 상황에서 shadow가 새어나오는 방식. 행동으로만 써야 한다. 감정 설명 금지.

**나쁜 예 — 감정 설명:**
```
"under_stress": "매우 불안해하고 두려움을 느낀다"
```

**좋은 예 — 행동 묘사:**
```
"under_stress": "혼자 편의점에 간다. 캔맥주 두 개를 사고 아무 말 없이 돌아온다. 다음 날 아무 일 없었다는 듯 웃는다."

"under_stress": "갑자기 청소를 시작한다. 아무도 건드리지 않은 서랍을 꺼내 정리한다. 말을 걸면 '응, 아무것도 아니야'라고 한다."
```

---

## 9. `speaking_examples` 작성법

shadow를 숨기려는 사람의 말은 **불완전하고 회피적이다.**

**좋은 대사의 특징:**
- 문장이 짧고 끊긴다 (말줄임표 `...` 활용)
- 감정 단어를 안 쓴다 ("슬프다", "화난다" 금지)
- shadow를 숨기는 방향으로 흐른다

```json
"speaking_examples": [
  "그게... 뭐, 다 잘 될 거야. 걱정하지 마.",
  "나 좀 혼자 있게 해줘. 잠깐만.",
  "미안해. 내가 좀 더 잘할게.",
  "...그냥 넘어가자. 우리 이러지 말자."
]
```

---

## 10. `situations` 작성법

**이번 시리즈에서 선택할 출발 사건.** 성격 묘사가 아니라 이미 벌어진 사건으로 쓴다.
shadow가 드러날 수 있는 상황을 넣을수록 대본이 흥미로워진다.

**공식:**
```
[구체적 사건 + 숫자/기간] — [이 사건이 만드는 갈등 구조]
```

```json
"situations": [
  "전세 만기 3개월 — 집주인이 보증금 반환을 거부하고 있다",
  "회사 구조조정 대상에 올랐지만 아내에게 숨기고 있다",
  "주식 투자 실패로 2천만 원 손실 — 아무도 모른다",
  "전세 사기 피해자 모임에 나갔다가 거기서 다른 여자를 만났다",
  "과거 연쇄살인마였다 — 현재는 평범한 가장으로 15년을 살았다"
]
```

마지막 예시처럼 극단적인 shadow도 상황으로 넣을 수 있다.
Gemini는 이것을 `현재 상황`으로 받아서 그에 맞는 장면을 쓴다.

---

## 11. Gemini 프롬프트 주입 경로

| 필드 | 주입 방식 | 조건 |
|---|---|---|
| `public_face` | `- 겉모습 (남들이 보는 모습): ...` | 자동 (선택 불필요) |
| `shadow` | `- 속모습 (절대 들키고 싶지 않은 진짜 모습): ...` | 자동 (선택 불필요) |
| `lie_to_self` | `- 자기기만 (서사 엔진): ...` | 자동 |
| `fear` | `- 가장 두려워하는 것: ...` | 자동 |
| `under_stress` | `- 극한 상황 반응 (shadow가 새어나오는 방식): ...` | 자동 |
| `speaking_examples` | `- 실제 대사 예시: ...` | 자동 |
| `situations` 중 1개 | `- 현재 상황: ...` | 사용자가 세계관 페이지에서 선택 |

## 12. shadow와 감정선의 연결

> **사건과 감정선은 별개로 작동하되, 특정 사건이 감정선의 변화를 유발할 수 있다.**
> 그 변화의 원인은 대부분 캐릭터의 `shadow`가 드러나거나 충돌하는 순간이다.

감정선(`emotionLines`)은 인물 간 관계의 현재 상태다. 챕터가 진행되면서 변할 수 있다.
이 변화는 `arc` 구조로 기록되며, 변화가 일어나는 챕터의 `storyBeats`에 트리거 사건이 명시된다.

```
shadow가 드러나는 사건 (storyBeat)
    ↓
감정선 상태 변화 (emotionLines.arc)
    ↓
다음 챕터 프롬프트에 새 상태 주입
```

**예시 — 박준혁의 shadow가 감정선을 바꾸는 흐름:**

```
shadow: "밤에 혼자 술을 마시며 다른 여자를 생각한다"
    ↓
storyBeat 챕터3: "전세 사기 모임에서 둘만의 저녁 → 감정선 변화: 호기심→설렘"
    ↓
emotionLines.arc["3"]: "설렘 — 선을 넘기 전 마지막 순간"
    ↓
storyBeat 챕터4: "선을 넘음 → 감정선 변화: 설렘→죄책감·집착"
    ↓
emotionLines.arc["4"]: "죄책감·집착 — shadow가 완전히 드러남"
```

**shadow를 쓸 때 감정선 변화 가능성도 함께 생각할 것:**

| shadow 내용 | 감정선 변화 트리거 가능성 |
|---|---|
| 비밀 연락, 감추는 만남 | 특정 챕터에서 상대 감정이 '의심→확신'으로 변화 |
| 과거 범죄·비밀 | 발각 시 '신뢰→배신감'으로 급변 |
| 숨겨진 욕망 | 표출 시 '착각→집착'으로 변화 |
| 자기기만적 선의 | 결말에서 '신뢰→환멸'로 반전 |

→ 상세 구조: [126 — 6-4-1절 사건·감정선 분리 원칙](126-영상자동화2-파이프라인-설계도.md)

## 14. 체크리스트

- [ ] `public_face` — 남들이 보는 이미지인가 (실제 속모습 X)
- [ ] `shadow` — 들키고 싶지 않은 것을 날것으로 썼는가 (점잖게 쓰지 않았는가)
- [ ] `public_face` ↔ `shadow` 간격이 충분히 큰가 (간격 = 드라마)
- [ ] `lie_to_self` — "믿는 것 — 진실" 대비 구조인가
- [ ] `fear` — shadow 노출 시 구체적 장면으로 썼는가
- [ ] `under_stress` — 행동 묘사인가 (감정 설명 X)
- [ ] `speaking_examples` — shadow를 숨기는 방향의 대사인가
- [ ] `situations` — 사건 + 갈등 구조 형태인가

---

> shadow를 잘 쓰는 기준: 이걸 SNS에 올리면 욕먹을 것 같다는 느낌이 들어야 한다.
> 그 수위가 독자가 "어, 이거 나 같은데?"라고 느끼는 수위다.
