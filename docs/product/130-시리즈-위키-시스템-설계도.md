## 1. 핵심 철학

> "RAG는 원본을 그대로 검색한다. Wiki는 AI가 원본을 이해하고 정리한다."

| 방식 | 동작 | 문제 |
|---|---|---|
| **RAG** | 원본 청크를 벡터 검색 → 프롬프트 주입 | 노이즈 많음, 맥락 단절, 업데이트 어려움 |
| **LLM Wiki** | AI가 원본을 읽고 지식 페이지로 재작성 | 정제된 지식, 누적 가능, 검색 불필요 |

LinkDrop은 LLM Wiki 패턴을 채택한다.
AI는 기자(실무자), 사용자는 편집장(방향 결정).

## 2. 아키텍처 — 3계층

```
C:/LinkDropV2/
├── source/{series_id}/          ← 계층 1: 원본 (절대 수정 금지, append-only)
│   ├── ch01__chapter__*.md      ← 챕터 대본 원본
│   └── url__*.md                ← 외부 소스 원본
│
├── wiki/{series_id}/            ← 계층 2: 위키 (AI가 정제한 지식)
│   ├── index.md                 ← 전체 목차 (항상 최신 유지)
│   ├── log.md                   ← append-only 작업 기록
│   ├── world.md                 ← 세계관 + 캐릭터 기본 정보
│   ├── foreshadows.md           ← 복선 추적
│   ├── timeline.md              ← 사건 타임라인
│   ├── facts.md                 ← NLM/기사 팩트 데이터 (NLM 쿼리 결과 자동 축적)
│   ├── theme.md                 ← 주제의식
│   ├── relationships.md         ← 인물 관계도 (init에서 자동 생성)
│   ├── props.md                 ← 반복 소품·상징물 (init에서 자동 생성)
│   └── character_arcs/{이름}.md ← 챕터별 심리 변화 (append-only)
│
└── apps/web/src/data/characters/ ← 계층 3: 글로벌 캐릭터 템플릿 (별도 관리)
    ├── _index.json
    └── {id}.json                 ← 22명 고정 아키타입 (성격/말투/공포/거짓말)
```

### 계층 분리 원칙

| 계층 | 내용 | 수정 주체 |
|---|---|---|
| source/ | 원본 그대로 보존 | 금지 (append-only) |
| wiki/ | 정제된 지식 페이지 | AI (ingest) + 사람 (UI 편집) |
| data/characters/ | 글로벌 캐릭터 아키타입 | 사람 (직접 JSON 편집) |

**캐릭터 중복 없음**: `data/characters/`가 글로벌 템플릿 제공 → `wiki/characters/` 폴더 불필요.
시리즈별 캐릭터 기본 설정은 `world.md`에 통합, 변화 추적만 `character_arcs/`에 분리.

## 4. 3대 오퍼레이션

### 4-1. INGEST (소스 → 위키 갱신)

```
입력: 원본 텍스트 (챕터 대본, URL, 사용자 메모)
  ↓
source/{series_id}/ 에 원본 보존 (절대 수정 금지)
  ↓
Gemini 호출 1회: 핵심 지식 추출 → JSON patch 배열 생성
  ↓
patch 적용: create / append / replace
  ↓
index.md + log.md 갱신
```

- AI 호출: **소스 1건당 1회**
- 출력 포맷: `[{slug, page_type, patch_kind, content_md}]`
- 트리거: 챕터 대본 완성 후 자동 (백그라운드), 또는 수동

### 4-2. QUERY (위키 → 대본 컨텍스트 제공)

```
챕터 역할(도입/전개/클라이맥스/결말) 파악
  ↓
index.md 먼저 확인 (전체 파일 읽기 금지)
  ↓
역할별 우선순위 페이지 5~7개 선별
  ↓
token_budget(6000자) 초과 시 summary(200자)로 대체
  ↓
=== WIKI CONTEXT === 블록으로 프롬프트 주입
```

- AI 호출: **0회** (파일 읽기만)
- 폴백: wiki 비어 있을 시 NLM 쿼리

#### 역할별 우선 페이지

| 챕터 역할 | 항상 포함 | 추가 포함 |
|---|---|---|
| 도입부 | world | facts, theme |
| 전개 | world | foreshadows, relationships, character_arcs/*, facts |
| 클라이맥스 | world | foreshadows, relationships, character_arcs/*, timeline |
| 결말 | world | foreshadows, character_arcs/*, timeline, theme |

### 4-3. LINT (위키 건강성 검수)

```
모든 wiki 페이지 수집
  ↓
최근 N개 챕터 소스 수집
  ↓
Gemini 호출 1회: 5개 항목 점검
  ↓
lint_report.md 저장
```

점검 항목:
1. 대본 퀄리티 — 첫 문장 강도, 이탈 구간, 감정 흐름
2. 정보 신뢰성 — 출처 검증 가능 여부
3. 지식 충돌 — 오래된 정보 vs 새 정보 모순
4. 고아 페이지 — 링크 없는 페이지
5. 미회수 복선 — planted 상태로 방치된 복선

## 5. 프롬프트 단일 소스 원칙

```
apps/api/prompts/
├── wiki_query.md    ← 글쓰기 원칙 단일 소스
│   └── <!-- SYSTEM_INSTRUCTION --> 블록
│       ├── 6개 글쓰기 원칙
│       ├── 리듬 예시
│       └── 벤치마크 예시
├── wiki_ingest.md   ← ingest 전용 프롬프트
└── wiki_lint.md     ← <!-- INCLUDE: wiki_query.md#SYSTEM_INSTRUCTION -->
                         (원칙을 query.md에서 인라인 참조)
```

`series_generate.py`도 `wiki_query.md`의 `SYSTEM_INSTRUCTION` 블록을 읽어 시스템 프롬프트로 사용.
원칙 변경 시 `wiki_query.md` 한 곳만 수정하면 전체 반영.

## 6. Cold Start 플로우

```
세계관 설정 완료 (world/page.tsx handleProceed)
  ↓
seriesId 생성: topic → slug ("이혼_전문_변호사_2026" 형태, 파일시스템 안전)
sessionStorage['series_world']에 seriesId 명시 저장
  ↓
/api/wiki/init 즉시 호출 (동기, 세계관 확정 시점에 바로 실행)
  ↓
init_wiki_from_world():
  - world.md 생성 (세계관 + 캐릭터 기본 정보)
  - character_arcs/{이름}.md 생성 (빈 파일)
  - foreshadows.md / timeline.md / facts.md / theme.md 생성
  - relationships.md / props.md 생성 (stub)
  - index.md / log.md 초기화
  ↓
챕터 1 대본 생성 → wiki 비어 있음 → NLM 폴백 (팩트 쿼리)
SSE 첫 이벤트: {wiki_used: false} → 화면에 "NLM 폴백" 배지 표시
  ↓
챕터 1 완성 → background:
  ① ingest_chapter() → world/timeline/foreshadows/character_arcs 갱신
  ② NLM facts → ingest_source(nlm_query) → facts.md 축적
  ↓
챕터 2부터 → wiki context 주입 (NLM 폴백 불필요)
SSE 첫 이벤트: {wiki_used: true} → 화면에 "위키 컨텍스트 적용됨" 배지 표시
```

### seriesId 정규화 규칙

```
topic: "이혼 전문 변호사 드라마"
  ↓
replace(/[^\w가-힣]/g, '_')  →  "이혼_전문_변호사_드라마"
replace(/_+/g, '_')          →  "이혼_전문_변호사_드라마"
slice(0, 40) + '_' + year    →  "이혼_전문_변호사_드라마_2026"
```

wiki_service.py의 `_safe_id()`가 추가로 경로 위험 문자를 제거하므로 이중 보호.

## 8. UI — /series/wiki 페이지

- **120UI 패턴**: 좌측 카드 그리드(260px) + 우측 콘텐츠 패널
- **타입 필터**: 전체/세계관/인물변화/관계도/타임라인/복선/팩트/소품/주제
- **페이지 뷰**: pre 포맷 마크다운 텍스트
- **편집**: textarea → PUT 저장
- **로그 탭**: 챕터별 작업 이력
- **series_id**: sessionStorage `series_world.seriesId`에서 자동 로드 (slug 형태로 보장)
- **🔍 건강성 점검 버튼**: POST /api/wiki/lint → 결과 모달 팝업 (Gemini 1회)
- **소스 주입 패널** (하단): 제목/타입(메모·텍스트·URL)/내용 → "위키에 주입" → POST /api/wiki/sources/ingest

## 12. writing_guide.md — 살아있는 글맛 스타일 가이드

> 추가일: 2026-04-08
> 목적: AI가 쓴 글이라는 말을 듣지 않기 위한 "독자 감정 설계 기준" 누적 시스템

### 핵심 철학

기술적 글쓰기는 AI가 이미 인간을 넘었다.
그러나 AI 글이 독자에게 외면받는 이유는 **온도와 숨결이 없기 때문**이다.

유명 작가들의 인기 비결은 구조가 아니라 **독자가 페이지를 넘기게 만드는 그 한 문장**에 있다.
이 패턴은 추출 가능하고, 구조화 가능하다.

### writing_guide.md 위치

```
C:\LinkDropV2\source\_shared\writing_guide.md
```

이 파일은 Gemini 대본 생성 시 **system instruction 레벨**로 주입된다 (최고 우선순위).

### AI 글이 들키는 3가지 패턴 — 반드시 회피

| 패턴 | AI 글 | 작가 글 |
|---|---|---|
| 감정 표현 | "그녀는 슬펐다" (설명) | "손 한 번만 잡아달라 했다가 뿌리쳐졌다" (장면) |
| 갈등 구조 | 정리되고 깔끔한 갈등 | 지저분하고 모순된 감정 (현실) |
| 침묵 | 항상 대사로 설명 | 대사 없이 분위기만으로 전달 |

### 소설 분석 시 Claude가 추출해야 할 것

소설 파일이 `source/_shared/` 에 추가되면 Claude가 읽고 아래 기준으로 분석 후 `writing_guide.md` 섹션 9에 추가한다.

**추출 기준 4가지:**

1. **설명하지 않고 보여준 것** — 작가가 말하지 않고 독자가 스스로 느끼게 한 장치
2. **독자 이탈 방지 구간** — 첫 문단의 훅, 클리프행어 직전 문장 구조
3. **모순된 감정 처리** — 두 가지 상반된 감정을 한 문장/장면에 담은 방식
4. **악역이 주인공을 도운 구조** — 악역의 행동이 오히려 주인공에게 유리해진 메커니즘

**추출 형식:**

```markdown
### {소설 제목} ({작가}) — {장르/테마}
- **훅 장치**: [첫 문단에서 독자를 잡은 방법]
- **침묵 장면**: [대사 없이 감정을 전달한 방식]
- **모순 감정**: [역설적 감정 처리 예시]
- **악역 활용**: [악역이 주인공을 도운 구조]
- **쓸 수 있는 장면**: "[직접 인용 또는 재구성 예시]"
```

### 피드백 루프 — 장기 계획

```
소설 축적 (source/_shared/)
    ↓
Claude 분석 → writing_guide.md 업데이트 ("writing_guide 갱신해줘" 한 마디)
    ↓
Gemini system instruction에 주입 → 대본 생성
    ↓
네이버 웹소설 등록 → 독자 반응 수집
    ↓
댓글/이탈 구간/반응 패턴 → writing_guide 추가 반영
    ↓
다음 시리즈에 적용
```

30편 이상 축적 시 → "독자가 이탈하지 않는 글의 공통 구조" 데이터 확보.
이것이 LinkDrop만의 글맛 DNA가 된다.

### 운영 규칙

- 소설 파일 형식: `.txt` / `.md` (`.pdf` / `.vtt` / `.srt` 도 지원)
