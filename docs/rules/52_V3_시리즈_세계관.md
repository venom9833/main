## 1. 개요

시리즈 생성 시 Gemini가 만들어 내는 "평균값 세계관"을 방지하기 위해, 사용자가 **핵심 세계관 설정 2가지**를 사전 확정하면 Gemini가 해당 설정을 중심축으로 삼아 세계관을 생성하는 구조다.

- **갈등 해소 방식** (resolution_methods) — 이야기의 결말 방향성
- **서술 시점** (narrative_povs) — 챕터 전체의 화자 구조

나머지 4개 차원(배경, 관계, 사회적 균열, 갈등 구조)은 Create 페이지에서 노출하지 않고 **Gemini 자유 생성**에 맡긴다. WorldEditor에서 사후 조정 가능.

### 2-2. 각 옵션 항목 필드

```json
{
  "id": "bg_01",
  "label": "폐광촌 진폐증 요양원",
  "tension": "국가에 버려진 사람들",
  "scene": "1989년 겨울, 산소호흡기 소리만 가득한 8인 병실. 누군가 면회를 왔다.",
  "category": "현실적"  // resolution_methods에만 존재
}
```

- **`scene`**: Gemini `openingHook` 프롬프트 앵커로 주입됨. **시간·장소·행동 중 하나로 시작**해야 함. 개념 정의·감상 시작 금지.
- **`category`**: `resolution_methods`에만 존재. `"현실적"` 또는 `"비현실적"`.
  - `"비현실적"` → Gemini에 "초자연·판타지 요소를 결말에 자연스럽게 녹일 것" 지시 추가
  - `"현실적"` → "기억상실·타임슬립·초자연 요소로 마무리 금지" 지시 추가

## 3. 세계관 생성 파이프라인

### 3-1. 흐름

```
Create 페이지
  └─ 주제 입력 + 파일 업로드 + (옵션 2개 선택)
       │
       ├─ POST /api/v1/series → 시리즈 생성
       ├─ POST /api/v1/wiki/{id}/sources/upload-file → 파일 인제스트
       │     └─ source_analyzer.py → world_data.source_summary 저장
       ├─ PATCH /api/v1/series/{id}/world → selectedOptions 저장
       └─ POST /api/v1/series/{id}/approve/source_upload
              └─ world_service.run_world() 호출
                   ├─ source_summary 존재? → Python 분석 결과 사용
                   │   없으면 → RAG (pgvector search)
                   ├─ selectedOptions → _build_selected_options_block()
                   └─ Gemini 1회 호출 → world JSON 생성
```

### 3-2. source_summary (Python 소스 분석)

파일 업로드 시 `source_analyzer.py`가 **Gemini 호출 없이** 순수 Python으로 분석.  
결과를 `world_data.source_summary`에 저장.

```python
# source_analyzer.analyze() 반환값
{
  "entities":      list[str],  # 최대 10개 핵심어
  "key_sentences": list[str],  # 최대 5개 핵심 문장
  "summary":       str,        # 300자 이내 요약
  "char_count":    int,
  "filename":      str,
}
```

`run_world()`에서 `source_summary` 존재 시 RAG(pgvector) 생략 → Gemini 임베딩 호출 0회.

### 3-3. _build_selected_options_block()

사용자 선택 옵션 → Gemini 프롬프트 제약 블록 변환.  
위치: `apps/api/services/world_service.py`

## 5. 설계 원칙

### 5-1. AI 평균화 문제 방지

Gemini는 학습 데이터의 통계적 평균을 출력하려는 경향이 있음.  
사용자가 결말 방향(해소 방식)과 화자 구조(시점)를 사전 확정하면, Gemini는 그 틀 안에서 창작 — 평균적 로맨스물 대신 **특정 결말을 향해 달리는 드라마**가 만들어짐.

### 5-2. 옵션 수 최소화 원칙

- v1.0: 6개 차원 × 평균 17개 = 102개 → 사용자 선택 부담 과다, Gemini 과제약
- v2.0: **Create 노출 2개 차원** (resolution 12 + pov 4), 나머지 4개 차원은 Gemini 자유 생성
- 총 선택지: **16개** (사용자 관점), DB 카탈로그: 78개 (WorldEditor에서 접근 가능)

### 5-3. 카테고리 분류 기준

`"비현실적"` 카테고리는 **실제 초자연·판타지 요소가 결말에 필수적인 경우만** 해당.  
죽음·희생·대리인 희생·운명적 재연결 등은 현실 드라마 안에서 충분히 구현 가능 → `"현실적"`.  
잘못 분류 시 Gemini가 현실 드라마에 판타지 요소를 강제 삽입하는 오염이 발생함.

### 5-4. scene 작성 기준

- `scene` 필드는 Gemini `openingHook`의 **앵커 장면**으로 주입됨
- 반드시 **시간·장소·행동 중 하나로 시작**해야 함
- 메타 서술("한 사람이 사라짐으로써...") 금지 — 구체적 시공간 장면으로 작성
- 특정 상황 강제 지양 (예: "아이를 안고" → 관계 특정이 됨)
