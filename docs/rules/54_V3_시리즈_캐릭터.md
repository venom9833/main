## 1. 개요

LinkDrop V3의 캐릭터는 **로컬 JSON 파일 기반 정적 라이브러리**다.
- Supabase 테이블 없음 — `apps/api/data/characters/` 폴더에서 직접 읽음
- AI 캐스팅 없음 — 트롭 태그 매칭으로 결정론적 선발
- 총 **27명**의 고정 인물 풀 (가족 그룹 3개 + 독립 인물)

> 캐릭터는 미리 정의된 인물 풀에서 선발한다. Gemini가 인물을 창작하지 않는다.

## 2. 파일 구조

```
apps/api/data/characters/
├── _index.json            # 경량 목록 (id/name/gender/age/role_pool/trope_tags) ← 코드 실사용
├── _all.json              # 전체 상세 통합본 (자동 생성) ← 현재 코드 미사용
├── _families.json         # 가족 그룹별 통합본 (자동 생성) ← 현재 코드 미사용
├── families.json          # 가족 그룹 정의 ← 현재 코드 미사용
├── kim_th.json            # 개별 캐릭터 상세 ← 코드 실사용 (캐스팅·main.py)
├── kim_th_masako.json     # 마사코 화풍 이미지 생성 프롬프트 ← 현재 코드 미사용, 미래 필수
├── kim_th_real.json       # 실사 화풍 이미지 생성 프롬프트 ← 현재 코드 미사용, 미래 필수
├── ...
```

> `_emoline.json` 파일은 **폐기됨** — 감정선은 Supabase `character_emoline` 테이블로 완전 이전

### 2-1. 파일별 역할 상세

| 파일 | 코드 사용 여부 | 역할 | 비고 |
|------|--------------|------|------|
| `_index.json` | **실사용** | 캐스팅 엔진 진입점 (경량 목록) | `casting_service._load_all()` |
| `{id}.json` | **실사용** | 캐릭터 상세 (성격·situations·relationships·voice_id·photo URL) | `casting_service._load_detail()`, `main.py /characters` |
| `_all.json` | 미사용 | 전체 통합본 (자동 생성) | `casting_service`에 경로 변수 선언만 있고 read 없음 |
| `_families.json` | 미사용 | 가족 그룹 통합본 (자동 생성) | 어떤 라우터/서비스에서도 참조 없음 |
| `families.json` | 미사용 | 가족 그룹 정의 | 어떤 라우터/서비스에서도 참조 없음 |
| `{id}_masako.json` | **미사용 (보존 필수)** | fal-ai/flux-lora 마사코 화풍 이미지 생성 프롬프트 | fal.ai 백엔드 구현 시 필수 데이터 |
| `{id}_real.json` | **미사용 (보존 필수)** | fal-ai/flux-lora 실사 화풍 이미지 생성 프롬프트 | fal.ai 백엔드 구현 시 필수 데이터 |

> **`{id}_masako.json` / `{id}_real.json` 보존 이유**
> 현재 키프레임 파이프라인(Pillow 그라데이션 / Gemini 백엔드)에서는 읽히지 않는다.
> 그러나 이 파일들은 `fal_identity_prompt`, `style_prompt`, `negative_prompt`, `fal_params` 등
> **캐릭터 맞춤 이미지를 fal-ai/flux-lora로 생성할 때 필수인 원본 데이터**다.
> 삭제하면 캐릭터별 커스텀 이미지 생성 능력을 영구 상실한다. 반드시 보존.

> `_all.json`, `_families.json`, `families.json`은 현재 코드에서 미사용이지만
> 자동 생성 스크립트(`gen-characters.mjs`) 산출물이므로 재생성 가능. 삭제 보류 중.

- 캐릭터 추가/수정은 개별 `{id}.json` 파일만 편집 후 생성 스크립트 실행

## 3. 캐릭터 JSON 스키마

### 3-1. _index.json 항목 (경량)

```json
{
  "id": "kim_th",
  "name": "김태호",
  "gender": "male",
  "age": 53,
  "age_group": "중년",
  "occupation": "중견기업 부장 (25년차)",
  "family_group": "family_kim",
  "relation": "남편",
  "role": "묵묵히 버티는 중년 가장",
  "role_pool": ["protagonist", "affair_target"],
  "trope_tags": ["midlife_crisis", "office_romance", "marriage_strain", "affair_risk"],
  "villain_intensity": 0
}
```

### 3-2. 개별 상세 JSON 추가 필드

```json
{
  "voice_id": "dohyun",
  "photo_real_url": "https://.../characters/portraits/kim_th_real.jpeg",
  "photo_masako_url": "https://.../characters/portraits/kim_th_masako.jpeg",
  "core": {
    "personality":     "성격 설명",
    "speaking_style":  "말투 패턴 + 예시",
    "concern":         "현실적 걱정거리",
    "fear":            "가장 두려워하는 것",
    "lie_to_self":     "스스로에게 하는 거짓말 (→ Secret으로 활용)",
    "under_stress":    "스트레스 시 행동 패턴",
    "speaking_examples": ["실제 대사 예시 3~4개"]
  },
  "situations": [
    "현재 처한 상황 10가지 (1번이 메인 situation)",
    "★ 투입된 비밀: ..." // 비밀 투입 시 맨 앞에 추가됨
  ],
  "relationships": {
    "타인물명(관계)": "이 캐릭터가 상대를 어떻게 바라보는가"
  },
  "role_pool": ["protagonist", "affair_target"],
  "trope_tags": [...],
  "villain_intensity": 0
}
```

### 3-3. 필드 의미

| 필드 | 의미 |
|------|------|
| `voice_id` | edge-tts 성우 ID → `tts_service.VOICE_MAP`으로 음성명 해석 |
| `lie_to_self` | `casting_service`가 `charASecret`으로 복사 → 대본 복선 재료 |
| `situations[0]` | `casting_service`가 `charASituation`으로 복사 → 세계관 생성 재료 |
| `villain_intensity` | 0=선인, 1=잠재적 갈등유발, 2=복합 빌런, 3=명백한 악역 |

## 7. 캐스팅 엔진 (casting_service.py)

### 7-1. 캐스팅 알고리즘

```
run_casting(series_id)
  │
  ├─ world_data.conflictTypes[0] → 트롭 결정
  │   없으면 → _infer_trope(topic, genre) → 키워드 매핑
  │
  ├─ cast_for_trope(trope, seed=hash(series_id) % 10000)
  │   ├─ 주인공 2명: role_pool=protagonist, 남/여 균형, 트롭 점수 내림차순
  │   ├─ 빌런 1명:   role_pool=antagonist, villain_intensity 내림차순
  │   ├─ 촉매 2명:   role_pool=catalyst, 트롭 태그 매칭 우선
  │   ├─ 시니어 1명: role_pool=elder
  │   ├─ 거울 1명:   role_pool=mirror
  │   └─ 보충: 트롭 태그 매칭 캐릭터로 총 8명 채움 (최대 10명)
  │
  └─ world_data에 저장
      charA / charAName / charAVoice / charAOccupation /
      charASpeakingStyle / charASecret / charASituation /
      charAFear / charAPersonality / charAFaceGrid
      (charB 동일)
      castTrope / fullCast / fullCastDetails
```

- `seed = hash(series_id) % 10000` — 동일 시리즈는 항상 동일 캐스팅 재현
- `recent_ids` 지원 — 최근 시리즈에서 사용된 인물을 후순위로 밀어 다양성 확보
- **AI 호출 0회** — 완전 결정론적 알고리즘

### 7-2. 트롭 추론 (_infer_trope)

`world_data.conflictTypes`에 트롭이 없으면 topic + genre 텍스트에서 키워드 매핑으로 추론.
매핑 실패 시 기본 트롭 = `"affair"`.

## 8. 비밀 투입 시스템 (apply_user_secrets)

대본 생성 전 사용자가 각 캐릭터에 비밀을 투입할 수 있다.

```
CastingReviewPanel → 비밀 입력
  → POST /series/{id}/approve/casting { userSecrets: { char_id: "비밀 내용" } }
  → apply_user_secrets(userSecrets, world)
      ├─ character JSON situations[0]에 "★ 투입된 비밀: ..." 영구 추가 (파일 직접 수정)
      ├─ world_data.fullCastDetails 동기화
      └─ 조연(index >= 2)에게 비밀 투입 시 → elevatedCast에 추가 (주연급 비중 격상)
```

- 비밀은 **캐릭터 JSON 파일에 영구 저장** (`situations` 맨 앞)
- 중복 방지: `"★ 투입된 비밀:"` 접두사로 시작하는 기존 항목은 교체
- `elevatedCast`: 조연이지만 비밀이 투입된 경우 → 대본 프롬프트에 주연급으로 추가

## 11. 캐릭터 추가 방법

1. `apps/api/data/characters/{새id}.json` 파일 작성 (kim_th.json 형식 참조)
2. `voice_id` 지정 (VOICE_MAP에 있는 값 사용)
3. `role_pool`, `trope_tags`, `villain_intensity` 설정
4. `scripts/gen-characters.mjs` 실행 → `_index.json`, `_all.json`, `_families.json` 자동 재생성

## 12. 감정선 시스템 (emoline)

### 12-1. 개요

감정선은 **캐릭터 간 관계의 감정 타입을 시각적으로 정의하는 전역 영구 데이터**다.

- 시리즈가 끝나도 유효 — 매 시리즈 생성 시 자동 참조
- 사용자가 명시적으로 수정하지 않는 한 유지
- ReactFlow 노드-엣지 그래프로 편집
- **Gemini 대본 생성에 직접 주입** (시놉시스·세계관·챕터 대본 3단계)

### 12-2. 저장 구조

**Supabase `character_emoline` 테이블** (단일 전역 행)

```sql
id              integer primary key  -- 항상 1
edges           jsonb                -- ReactFlow 엣지 배열
node_positions  jsonb                -- 캐릭터 카드 위치 배열 (x/y 좌표)
updated_at      timestamptz          -- 자동 갱신 트리거
```

엣지 항목 구조:
```json
{
  "id": "kim_th-lee_sj-1713800000000",
  "source": "kim_th",
  "target": "lee_sj",
  "type": "emotionEdge",
  "data": { "label": "착각", "color": "#7c3aed" }
}
```

노드 위치 항목 구조:
```json
{ "id": "kim_th", "x": 120, "y": 340 }
```

- `source` / `target`: 캐릭터 ID (`_index.json` 기준)
- `data.label`: EMOTION_TYPES 11종 중 하나
- `data.color`: 라벨에 대응하는 고정 색상 코드
- `node_positions`: 저장된 캐릭터 ID가 있으면 위치 복원, 없으면 `buildInitialNodes` 기본 배치
- 서버 재배포·컨테이너 재시작과 무관하게 **영구 보존**

### 12-3. EMOTION_TYPES (11종)

| 라벨 | 색상 | 서사 의미 |
|------|------|-----------|
| 로맨스 | #db2777 | 상호 감정 인지, 진전 가능 |
| 짝사랑 | #9333ea | 일방적 감정 |
| 착각 | #7c3aed | 한쪽이 오해로 감정 발전 |
| 불륜 | #dc2626 | 금지된 관계 실행 |
| 금지된 감정 | #ea580c | 불륜 직전, 감정만 있는 상태 |
| 그리움·미련 | #0d9488 | 전 연인·이혼 후 잊지 못하는 감정 — 로맨스와 구분 |
| 위로·의지 | #0369a1 | 위기 상황에서 형성되는 의존 |
| 집착 | #4f46e5 | 일방적·강박적 집착 |
| 경쟁·질투 | #b45309 | 우열 경쟁, 감정적 질투 |
| 가족 | #059669 | 혈연·가족 관계 |
| 적대 | #6b7280 | 갈등·대립 |

### 12-4. API 엔드포인트

| 메서드 | 경로 | 요청/응답 | 설명 |
|--------|------|-----------|------|
| `GET` | `/api/v1/emoline` | `{ edges, node_positions }` | 저장된 엣지 + 노드 위치 반환 |
| `POST` | `/api/v1/emoline` | `{ edges, node_positions }` | 엣지 + 노드 위치 Supabase 저장 |
| `GET` | `/api/v1/emoline/preview` | `{ prompt, edge_count, edges[] }` | 실제 Gemini 주입 텍스트 + 엣지 상세 반환 (전달 검증용) |

- `POST` 페이로드: `node_positions = [{ id, x, y }, ...]` — 현재 canvas의 모든 노드 좌표 포함
- 자동 저장 (디바운스 800ms) — 엣지 변경 시 자동 호출 (노드 위치 동시 저장)
- 수동 저장 — "저장" 버튼 클릭 시 즉시 호출 (노드 위치 동시 저장)
- `emoline/preview`: Supabase 저장값 기준으로 `_build_emoline_block()` 실행 → 실제 백엔드 주입 텍스트 그대로 반환

### 12-5. 프론트엔드 페이지

**URL**: `/characters/emoline`

**파일**: `apps/web/src/app/characters/emoline/page.tsx`

**GNB**: `LinkDrop V3 | 내 시리즈 | 새 시리즈 | 캐릭터 | 감정선`

**주요 컴포넌트**

| 컴포넌트 | 역할 |
|----------|------|
| `CharactersEmolineFlow` | ReactFlow Provider + 전체 상태 관리 |
| `CharacterNode` | Dark Liquid Glass 캐릭터 노드 (situations 최대 4개 미리보기) |
| `CharacterDetailPanel` | 우측 사이드 패널 — 선택된 캐릭터 전체 상황 목록 + 추가/삭제 |
| `EmotionEdge` | 커스텀 베지어 엣지 (라벨 + × 삭제 버튼) |
| `EdgeTypePopup` | 연결 시 감정 타입 선택 팝업 |
| `VerifyModal` | `/api/v1/emoline/preview` 실 API 호출 → 실제 Gemini 주입 텍스트 표시 |

**동작 흐름**

```
페이지 진입
  → GET /api/v1/characters (27명 + situations)
  → GET /api/v1/emoline (저장된 엣지 + node_positions 복원)
  → buildInitialNodes()로 노드 생성 후 저장된 좌표로 덮어씌우기
  → ReactFlow 렌더링

노드 클릭 → CharacterDetailPanel 열림
  → GET /api/v1/characters/{id} 없이 이미 로드된 데이터 표시
  → situations 전체 목록 (★ 투입된 비밀: 빨간색 강조)
  → × 버튼 → DELETE /api/v1/characters/{id}/situations/{index}
  → "상황 추가" 입력 → POST /api/v1/characters/{id}/situations

노드 드래그 → 위치 변경
  → "저장" 클릭 → POST /api/v1/emoline { edges, node_positions }
  → 다음 접속 시 동일 위치로 복원

노드 핸들 드래그 → EdgeTypePopup 팝업
  → 감정 타입 선택 → 엣지 추가
  → 800ms 디바운스 자동 저장 → POST /api/v1/emoline { edges, node_positions }

"전달 검증" 클릭 → VerifyModal
  → GET /api/v1/emoline/preview 호출 (로딩 표시)
  → 엣지별 카드 (source→target: 감정, 양쪽 상황)
  → 실제 Gemini 프롬프트 삽입 블록 표시

"저장" 버튼 클릭 → POST /api/v1/emoline { edges, node_positions } (즉시)
```

**노드 레이아웃**
- 기본: 가족 그룹별 열 배치 (박씨 → 김씨 → 최씨 → 주변 인물)
- `supporting` 그룹이 6명 이상이면 자동 2열 분할
- 저장된 `node_positions`가 있으면 기본 배치 무시하고 저장 좌표 우선 적용
- 신규 추가된 캐릭터(저장 좌표 없는 경우)는 기본 배치 좌표 사용

**카드 스타일**
- 남성: 배경 `#222222`
- 여성: 배경 `#111111`
- 카드 고정 너비: `360px`
- 감정 타입 범례: 좌상단 고정 (2열 그리드)
- Controls (확대/축소/전체보기): 우상단 고정, Dark 테마

### 12-6. Gemini 프롬프트 주입 (구현 완료)

**구현 파일**: `apps/api/services/script_service.py`

**흐름**:
```
run_script()
  → Supabase character_emoline 로드 (emoline_edges)
  → _build_narrative_prompt(..., emoline_edges)
      → _build_emoline_block(emoline_edges, world)
          → 현재 캐스트에 속한 엣지만 필터
          → 각 엣지: source→target: 감정타입 + 양쪽 캐릭터 상위 2개 상황
      → CONTEXT 블록에 "## 인물 관계 (감정선)" 섹션으로 주입
```

**주입 형식**:
```
## 인물 관계 (감정선 — 대본 서사에 반드시 반영)

- 김태호 → 이수진: **그리움·미련**
  [김태호 현재 상황] 명예퇴직 압박을 받고 있다 / 아내 몰래 부업을 시작했다
  [이수진 현재 상황] 옆집 김태호와 마주치는 횟수가 늘면서 감정이 흔들리고 있다 / ...

위 감정선은 인물 행동·대화·긴장감의 서사적 근거다.
감정선에 명시된 관계가 이번 챕터 장면에서 드러나야 한다.
```

**규칙**:
- 현재 시리즈 캐스트(`fullCastDetails`)에 **양쪽 모두 속한 엣지만** 포함
- 비밀(`★ 투입된 비밀:`)은 상황 목록에서 제외 — 인물 블록 `비밀` 필드에서 별도 처리
- 감정선이 없거나 캐스트 매칭 엣지가 0개면 블록 자체를 생략
