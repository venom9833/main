# fieldnote-book-workflow

경험서(1인칭 서사 + 실무 해설) 집필 전용 Claude 스킬.
저자의 실제 경험을 장면→맥락→원칙 구조로 풀어내는 6단계 집필 워크플로우.

---

## 이 스킬이 하는 일

저자가 "무엇을 썼느냐"가 아니라 "어떻게 판단했느냐"를 기록하는 책을 쓸 때 사용한다.
기획(Phase 1)부터 최종편집(Phase 5)까지 단계별로 Claude가 진행을 안내하고, 챕터 초안 작성·자가 점검·리라이팅을 수행한다.

---

## 파일 구성

```
fieldnote-book-workflow/
├── SKILL.md                 ← 워크플로우 절차 (메인)
├── writing-style-guide.md   ← 문체·어조·금지어 규칙
├── chapter-template.md      ← 챕터 구조 + 현장 노트·Before/After 형식 + 샘플 챕터 양식
└── chapter-checklist.md     ← 자가 점검·리라이팅·통합 점검·퇴고 체크리스트
```

---

## 전체 흐름

```
Phase 1: 기획
    ↓ 책 제목·독자·원재료·분량 등 7개 항목 확정
Phase 2: 목차 설계
    ↓ 챕터별 시놉시스·분량·원재료 활용 여부 포함
Phase 3: 챕터별 집필
    ↓ Step 1 초안 → Step 2 자가 점검 → Step 3 저자 피드백
      → Step 4 수정 → Step 5 리라이팅 (챕터 수만큼 반복)
Phase 3.5: 원고 통합 점검
    ↓ 전 챕터 통합 전 일관성·중복·[TODO] 마커 점검
Phase 4: 퇴고
    ↓ 구조 편집(Pass 1) → 문장 편집(Pass 2) → 교정(Pass 3)
Phase 5: 최종편집
    ↓ 서문·에필로그·부록·전체 검수
```

각 Phase는 저자의 확정 신호 후 다음 단계로 넘어간다.

---

## 핵심 집필 원칙

**"보여주되 가르치지 않는다"**

모든 챕터는 세 덩어리로 구성한다.

- **장면 (30%)**: 날짜·도구·작업 내용이 보이는 구체적 에피소드
- **맥락 (40%)**: 왜 그런 선택을 했는지, 무엇이 문제였는지
- **원칙 (30%)**: 경험에서 뽑아낸 판단 기준 1~3개

---

## 설치 및 시작 방법

**1. Claude 프로젝트 생성**
Claude.ai에서 새 프로젝트를 만든다.

**2. 파일 업로드**
4개 파일(`SKILL.md`, `writing-style-guide.md`, `chapter-template.md`, `chapter-checklist.md`)을 프로젝트 지식에 업로드한다.

**3. 시작 메시지 입력**
프로젝트 채팅창에 아래와 같이 입력한다.

```
경험서를 쓰려고 해. fieldnote-book-workflow 스킬로 Phase 1부터 시작해줘.
```

Claude가 책 제목, 독자, 원재료 등을 순서대로 질문한다.

---

## 각 단계별 시작 방법

### Phase 1: 기획

**언제 시작하나**
스킬을 처음 사용할 때. 책에 대해 아무것도 정해지지 않은 상태.

**시작 메시지**
```
경험서를 쓰려고 해. fieldnote-book-workflow 스킬로 Phase 1부터 시작해줘.
```

**진행 방식**
Claude가 아래 7개 항목을 2~3개씩 나눠 질문한다. 답변하면 된다.

```
1. 책 제목(가제)
2. 장르·형식 (경험서 / 실무 가이드 / 에세이 등)
3. 주요 독자 (직업, 수준, 이 책에서 얻고 싶은 것)
4. 저자 소개 (이름, 직함, 핵심 경력 한 줄)
5. 원재료 (블로그, 매거진, 뉴스레터, 강의 에피소드 등)
6. 목표 분량과 챕터 수
7. 종결어미 스타일 (~한다체 / ~합니다체)
```

모든 항목이 확정되면 Claude가 책 프로필 표를 제시한다.
"확정", "맞아", "OK" 등을 입력하면 Phase 2로 넘어간다.

**이미 일부 내용이 정해진 경우**
처음부터 알고 있는 정보를 같이 입력해도 된다.

```
경험서를 쓰려고 해. fieldnote-book-workflow 스킬로 Phase 1부터 시작해줘.
책 제목은 "20년차 강사의 AI 수업 일지"고, 독자는 현직 강사야.
나머지 항목은 질문해줘.
```

---

### Phase 2: 목차 설계

**언제 시작하나**
Phase 1 책 프로필이 확정된 직후. 또는 기획은 완료됐지만 목차가 없는 경우.

**시작 메시지**
Phase 1 직후라면 Claude가 자동으로 안내한다.
별도로 시작할 경우 아래와 같이 입력한다.

```
Phase 2 목차 설계를 시작해줘.
책 프로필은 다음과 같아.
- 가제: [제목]
- 장르: [장르]
- 독자: [독자]
- 목표 분량: [분량]
- 원재료: [원재료]
```

**진행 방식**
Claude가 전체 목차 초안을 제시한다. 각 챕터에 시놉시스, 예상 분량, 원재료 활용 여부가 붙어 있다.

수정이 필요하면 구체적으로 지시한다.

```
3챕터 제목을 바꿔줘. "실패의 기록"으로.
5챕터와 6챕터 순서를 바꿔줘.
Part 2를 하나 더 추가해줘. 주제는 "도구 선택 기준"이야.
```

목차가 마음에 들면 확정 신호를 입력한다.

```
목차 확정. docx로 저장해줘.
```

---

### Phase 3: 챕터별 집필

**언제 시작하나**
목차가 확정된 직후. 챕터를 하나씩 순서대로 작성한다.

**시작 메시지**
아래 형식으로 입력한다. 핵심 장면과 도출할 원칙은 반드시 포함한다.

```
[장 작성 요청]
■ 장 번호/제목: Ch1. 처음으로 AI에게 원고를 넘긴 날
■ 원재료 참조: 블로그 2023년 8월 글 "ChatGPT로 초안 쓰기"
■ 핵심 장면: 초안을 받아보고 문장이 매끄럽지만 내 목소리가 없다는 걸 느낀 순간
■ 도출할 원칙: AI 초안은 구조 재료다. 문장은 저자가 다시 써야 한다.
■ 분량 지정: 5,000자
```

핵심 장면과 도출할 원칙이 빠지면 Claude가 해당 항목만 질문한다.

**챕터 내부 5단계 흐름**

Claude가 초안을 작성하면(Step 1·2) 읽고 피드백을 준다(Step 3).

```
Step 3 피드백 예시:
"두 번째 문단 장면이 너무 짧아. 더 구체적으로 늘려줘."
"원칙 부분 톤이 너무 교훈적이야. 판단 기준 형태로 바꿔줘."
"분량이 너무 많아. 맥락 부분을 절반으로 줄여줘."
```

수정이 끝나면 리라이팅을 요청한다.

```
리라이팅 해줘.
```

리라이팅 완성 후 저장 여부를 확인하는 메시지가 뜬다.
다음 챕터로 넘어가려면 같은 방식으로 장 작성 요청을 반복한다.

**원재료(블로그, 매거진 등)를 직접 붙여넣는 경우**

```
[장 작성 요청]
■ 장 번호/제목: Ch3. 프롬프트를 설계한다는 것
■ 원재료 참조: 아래 블로그 글 참고해줘.
■ 핵심 장면: 프롬프트를 수십 번 고치다가 결국 질문 자체를 바꾼 순간
■ 도출할 원칙: 프롬프트 수정보다 질문 구조 재설계가 먼저다.
■ 분량 지정: 5,000자

[원재료 붙여넣기]
(블로그 글 전문)
```

---

### Phase 3.5: 원고 통합 점검

**언제 시작하나**
모든 챕터 집필이 완료된 직후. Phase 4 퇴고 전에 반드시 거친다.

**시작 메시지**
```
모든 챕터 작성이 끝났어. Phase 3.5 원고 통합 점검을 시작해줘.
```

**진행 방식**
Claude가 9개 점검 항목을 적용하고 결과를 제시한다.

- 용어 불일치, 에피소드 중복, 종결어미 이탈, [TODO] 마커 잔존 현황 등을 확인한다.
- 문제가 발견되면 Claude가 수정 방향을 제안한다. 저자가 판단 후 수정을 지시한다.

점검이 끝나면 통합 원고 저장 여부를 결정한다.

```
통합 원고 docx로 저장해줘.
```

---

### Phase 4: 퇴고

**언제 시작하나**
Phase 3.5 통합 점검이 완료된 직후.

**시작 메시지**
```
Phase 4 퇴고를 시작해줘.
```

**진행 방식**
Claude가 3회 패스를 순서대로 적용하고 각 Pass 결과를 제시한다.

- **Pass 1 구조 편집**: 서사 아크, 챕터 흐름, 교훈 강요 문장 잔존 여부 등 9항목
- **Pass 2 문장 편집**: 문장 길이, 종결어미, 리듬, 금지어 등 8항목
- **Pass 3 교정**: 맞춤법, 사실관계, [TODO] 마커 최종 제거, 글자 수 기록

각 Pass 결과를 확인하고 추가 수정이 필요하면 지시한다.

```
Pass 1 결과 확인했어. 7번 항목 해당 챕터 다시 써줘.
Pass 2 진행해줘.
```

퇴고가 끝나면 저장 여부를 결정한다.

```
퇴고 원고 docx로 저장해줘.
```

---

### Phase 5: 최종편집

**언제 시작하나**
Phase 4 퇴고가 완료된 직후.

**시작 메시지**
```
Phase 5 최종편집을 시작해줘.
```

**진행 방식**
Claude가 아래 항목을 순서대로 안내한다.

```
1. 서문 작성
2. 에필로그 작성
3. 각 챕터 도입부 첫 문장 최종 확인
4. 현장 노트 시간 순서 점검
5. 부록 구성 (원재료 목록·참고 도구·용어 정리)
6. 전체 흐름 최종 검수
```

서문과 에필로그는 Claude가 초안을 작성하고 저자가 피드백을 준다.
나머지 항목은 Claude가 점검 결과를 제시하고 저자가 확인한다.

모든 항목이 완료되면 최종 완성본 저장 여부를 결정한다.

```
최종 완성본 docx로 저장해줘.
```

## 산출물

모든 결과물은 기본적으로 대화창 텍스트로 제공한다.
각 단계 완료 후 저자가 요청하면 `.docx` 파일로 저장한다.

| 단계 | 파일명 |
|------|--------|
| Phase 2 목차 | `02-table-of-contents.docx` |
| Phase 3 챕터 초안 | `chapter-XX-draft.docx` |
| Phase 3 챕터 완성본 | `chapter-XX-final.docx` |
| Phase 3.5 통합 점검 | `03-integration-report.docx` |
| Phase 3.5 통합 원고 | `03-manuscript-full.docx` |
| Phase 4 퇴고 원고 | `04-manuscript-edited.docx` |
| Phase 4 편집 리포트 | `04-editing-report.docx` |
| Phase 5 최종 완성본 | `05-manuscript-final.docx` |

## 이 스킬이 맞는 책

- 저자의 실제 경험을 1인칭으로 기록하는 책
- 방법론보다 판단 기준을 전달하려는 실무서
- 블로그·매거진·뉴스레터·강의 에피소드 등 기존 원재료가 있는 경우

## 이 스킬이 맞지 않는 책

- 정보 전달 중심의 입문서·교재
- 소설·에세이·자기계발서
- 원재료 없이 처음부터 새로 쓰는 책

---

## 주의사항

- Phase 1에서 확정한 **종결어미**는 전체 원고에서 바꾸지 않는다
- 챕터 작성 시 **"핵심 장면"과 "도출할 원칙"** 2개가 없으면 초안을 시작하지 않는다
- 원재료는 그대로 옮기지 않는다. 책의 서사 흐름에 맞게 재구성한다
