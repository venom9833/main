# fieldnote-book-workflow — 경험서 집필 스킬

이 스킬은 저자의 실제 경험을 1인칭 서사로 풀어내는 경험서 집필 전용 도구다.
Phase 1(기획)부터 Phase 5(최종편집)까지 순서대로 진행한다.

---

## 보조 파일 목록

| 파일 | 용도 | 읽는 시점 |
|------|------|----------|
| `writing-style-guide.md` | 문체 정의, 어조, 금지어 규칙 | Phase 3 초안 작성 전 |
| `chapter-template.md` | 챕터 내부 구조, 현장 노트·Before/After 형식, 샘플 챕터 양식 | Phase 3 초안 작성 전 |
| `chapter-checklist.md` | 자가 점검, 리라이팅, 퇴고 체크리스트 | Step 2·5·Phase 4 |

---

## 전체 흐름

```
Phase 1: 기획 → Phase 2: 목차설계 → Phase 3: 챕터별 집필 → Phase 3.5: 원고 통합 점검 → Phase 4: 퇴고 → Phase 5: 최종편집
```

각 Phase는 저자의 확정 신호를 받은 뒤 다음 단계로 넘어간다.
단계를 건너뛰지 않는다.

---

## Phase 1: 기획

### 진행 방식

저자에게 아래 항목을 순서대로 질문한다.
한 번에 전부 묻지 않고, 2~3개씩 나눠 질문한다.

```
1. 책 제목(가제)은 무엇인가?
2. 이 책의 장르·형식은? (경험서 / 실무 가이드 / 에세이 등)
3. 주요 독자는 누구인가? (직업, 수준, 이 책에서 얻고 싶은 것)
4. 저자 소개: 이름, 직함, 핵심 경력 한 줄
5. 원재료: 활용할 기존 콘텐츠가 있는가? (블로그, 매거진, 뉴스레터, 강의 에피소드 등)
6. 목표 분량과 챕터 수는? (예: 80,000자 / 16챕터)
7. 종결어미 스타일: ~한다체 / ~합니다체 중 선택
```

### 확정 후 처리

모든 항목이 확정되면 아래 책 프로필 표를 채워 저자에게 제시한다.
저자가 확인하면 아래 안내 문구를 출력하고 Phase 2로 넘어간다.

```
[책 프로필 확정]
| 항목       | 내용 |
|------------|------|
| 가제       |      |
| 장르       |      |
| 독자       |      |
| 종결어미   |      |
| 목표 분량  |      |
| 저자       |      |
| 원재료     |      |
```

**Phase 전환 안내 (Phase 1 완료 시 출력):**
```
Phase 1 기획이 확정되었습니다.
다음은 Phase 2 목차 설계입니다.
"Phase 2 시작해줘"를 입력하면 목차 설계를 시작합니다.
또한 첫 챕터 집필 전에 sample-chapter-template.md에
샘플 챕터를 작성해두면 이후 챕터의 문체·구조 기준점으로 활용할 수 있습니다.
```

## Phase 2: 목차 설계

### 진행 방식

Phase 1에서 확정된 책 프로필을 바탕으로 전체 목차를 설계한다.

**설계 원칙:**
- 전체 흐름은 **도입 → 시행착오 → 체계 구축 → 성찰** 순서를 기본으로 한다
- 각 챕터에 시놉시스(2~3문장), 예상 분량, 원재료 활용 여부를 붙인다
- 파트(Part)가 있는 경우 파트별 흐름도 함께 제시한다

**목차 출력 형식:**
목차는 아래 형식으로 출력한다. 형식을 바꾸지 않는다.

```
[목차 초안]

## PART 1. 파트 제목 (해당 시)

### Ch1. 챕터 제목
- 시놉시스: (2~3문장. 이 챕터에서 다루는 것, 독자가 얻는 것)
- 예상 분량: 0,000자
- 원재료: (활용할 원재료 제목/출처. 없으면 "신규")

### Ch2. 챕터 제목
- 시놉시스:
- 예상 분량:
- 원재료:

(이하 동일 형식 반복)

---
총 챕터 수: 00개
총 예상 분량: 000,000자
```

**목차 초안 제시 후:**
저자가 수정 피드백을 주면 반영한다.
저자가 확정 신호("확정", "이대로 진행", "OK" 등)를 주면 확정 처리한다.

### 확정 후 처리

확정된 목차는 `references/confirmed-toc.md`로 저장한다.
이후 모든 챕터 작업의 기준점이 된다. 목차 변경 시 이 파일을 업데이트한다.

저자에게 확인한다: "`confirmed-toc.md`로 저장할까요?"
저장 의사를 밝히면 파일 생성.

**Phase 전환 안내 (Phase 2 완료 시 출력):**
```
Phase 2 목차 설계가 확정되었습니다.
다음은 Phase 3 챕터별 집필입니다.

시작 전 권장 사항:
1. chapter-template.md 하단의 "샘플 챕터" 양식에
   가장 자신 있는 챕터 하나를 직접 작성해두세요.
   이후 모든 챕터의 문체·구조 기준점으로 활용됩니다.
2. 준비가 되면 아래 형식으로 첫 챕터 작성을 요청하세요.

[장 작성 요청]
■ 장 번호/제목:
■ 원재료 참조:
■ 핵심 장면:
■ 도출할 원칙:
■ 분량 지정:
```

## Phase 3: 챕터별 집필

### 집필 전 확인 사항

챕터 작성 요청을 받으면, 다음을 먼저 확인한다:

1. `writing-style-guide.md` 읽기 — 문체·금지어 기준 확인
2. `chapter-template.md` 읽기 — 챕터 구조, 보조 장치 형식, 샘플 챕터(저자 작성분) 확인
3. `references/confirmed-toc.md` 읽기 — 해당 챕터의 위치, 시놉시스, 예상 분량 파악
4. 원재료 활용 여부 확인 — 목차에 원재료 활용 챕터로 표시된 경우 해당 원문 참조
5. 앞뒤 챕터 연결 문장 금지 — 해당 챕터 주제에만 집중

### 챕터 작성 요청 시 확인 항목

저자가 챕터 작성을 요청하면 아래 항목을 확인한다.
저자가 자유 형식으로 입력해도 정보를 추출해 적용한다.

```
[장 작성 요청]
■ 장 번호/제목:
■ 원재료 참조: (블로그, 매거진, 강의 에피소드 등. 없으면 "신규")
■ 핵심 장면: 이 챕터에서 반드시 들어가야 할 구체적 에피소드는?
■ 도출할 원칙: 독자가 이 챕터에서 가져가야 할 판단 기준은?
■ 분량 지정: (미지정 시 5,000자 기본)
```

- "핵심 장면"과 "도출할 원칙" 2개가 빠진 채로 초안을 시작하지 않는다
- 나머지 항목이 빠지면 빠진 항목만 질문한다

### 챕터 작업 5단계

```
Step 1: 초안 → Step 2: 자가 점검 → Step 3: 저자 피드백 → Step 4: 수정 → Step 5: 리라이팅
```

#### Step 1. 초안 작성

`chapter-template.md`의 구조를 따라 작성한다.

1. 장면(Scene)부터 시작: 첫 문장은 시간·장소·행동 중 하나로 (개념 정의 시작 금지)
2. 장면 → 맥락 → 원칙 순서로 전개
3. 현장 노트 1~2개, Before/After 0~1개 배치
4. 챕터 끝: 요약이 아니라 관점의 재정렬로 마무리
5. `[TODO-유형: ...]` 마커 삽입

산출물: 초안 텍스트 (대화창 제공)

#### Step 2. 자가 점검

`chapter-checklist.md`의 **자가 점검** 항목을 적용한다.
하나라도 이탈 징후에 해당하면 해당 구간을 재작성한 뒤 제공한다.

산출물: 점검 결과 + [TODO] 마커 포함 초안 (대화창 제공)

#### Step 3. 저자 피드백

초안을 저자에게 제공하고 피드백을 받는다.
Claude는 초안을 제공한 뒤 저자의 수정 방향을 기다린다.
피드백은 자유 형식이다.

#### Step 4. 수정

- 피드백에서 지적한 부분만 수정한다. 지적하지 않은 부분은 원본을 유지한다
- 수정 후 Step 2 자가 점검을 다시 수행한다
- 저자가 추가 피드백을 주면 Step 3→4를 반복한다
- 저자가 "리라이팅 해줘" 또는 확정 신호를 주면 Step 5로 넘어간다

산출물: 수정본 텍스트 (대화창 제공)

#### Step 5. 리라이팅

`chapter-checklist.md`의 **리라이팅 체크리스트 10항목**을 순서대로 적용한다.
내용을 바꾸지 않는다. 같은 내용을 더 정확하고 읽기 좋은 문장으로 다듬는다.

**산출물 처리:**
완성본 텍스트 + 변경 내역표를 대화창에 제공한다.
제공 후 저자에게 확인한다: "`.docx` 파일로 저장할까요?"
- 저자가 저장 의사를 밝히면 `chapter-XX-final.docx`로 저장 후 제공
- 저장 의사가 없으면 대화창 텍스트로 마무리

모든 챕터가 완성될 때까지 이 5단계를 반복한다.

**Phase 전환 안내 (모든 챕터 완성 시 출력):**
```
모든 챕터 집필이 완료되었습니다.
다음은 Phase 3.5 원고 통합 점검입니다.
단일 원고로 합치기 전에 전체 일관성을 점검하는 단계입니다.
"Phase 3.5 시작해줘"를 입력하면 통합 점검을 시작합니다.
```

### 작업 유형별 분량 통제

- **"다듬어줘" / "수정해줘"** = 문장 수·문단 수·전체 구조 유지. 표현만 정리
- **"보강해줘"** = 지정 부분에 한해 내용 추가. 미지정 부분은 원본 유지
- **"추가해줘"** = 지정 위치에 지정 분량만 삽입
- 수정 결과물이 원본 대비 120%를 초과하면 초과 사유를 먼저 확인

### 장 간 일관성 규칙

- 동일 개념에 대해 장마다 다른 용어를 사용하지 않는다
- 이미 설명한 개념은 재설명 없이 "N장에서 다룬 [개념명]을 기준으로" 형태로 참조
- 파트 순서에 따라 난이도가 자연스럽게 상승한다

## Phase 3.5: 원고 통합 점검

전 챕터 집필 완료 후, 단일 원고로 통합하기 전에 점검한다.
`chapter-checklist.md`의 **통합 점검 체크리스트** 9항목을 적용한다.

산출물: 점검 결과 대화창 제공.
저자에게 확인한다: "통합 원고를 `.docx`로 저장할까요?"
저장 의사를 밝히면 `03-integration-report.docx` + `03-manuscript-full.docx` 저장.

**Phase 전환 안내 (Phase 3.5 완료 시 출력):**
```
Phase 3.5 원고 통합 점검이 완료되었습니다.
다음은 Phase 4 퇴고입니다.
구조 편집(Pass 1) → 문장 편집(Pass 2) → 교정(Pass 3) 순서로 진행합니다.
"Phase 4 시작해줘"를 입력하면 퇴고를 시작합니다.
```

- Pass 2: 문장 편집
- Pass 3: 교정

산출물: 퇴고 결과 대화창 제공.
저자에게 확인한다: "퇴고 원고를 `.docx`로 저장할까요?"

```
Phase 4 퇴고가 완료되었습니다.

서문·에필로그·부록 작성과 전체 독자 경험 최종 검수를 진행합니다.
"Phase 5 시작해줘"를 입력하면 최종편집을 시작합니다.
```

## Phase 5: 최종편집

1. **서문**: 저자가 이 분야를 시작한 이유, 이 책이 다루는 것과 다루지 않는 것, 독자에게 하는 약속
2. **에필로그**: 원재료에서 책이 되기까지의 과정, 이 책을 쓰는 과정 자체가 내용의 연장
3. **각 챕터 도입부 점검**: 첫 문장이 장면(시간·장소·행동)으로 시작하는지 최종 확인
4. **현장 노트 순서 점검**: 시간 순서가 자연스러운지 확인
5. **부록**: 원재료 목록, 참고 도구 목록, 용어 정리
6. **전체 흐름 최종 검수**: 처음부터 끝까지 독자 경험 점검

산출물: 최종 완성본 대화창 제공.
저자에게 확인한다: "최종 완성본을 `.docx`로 저장할까요?"
저장 의사를 밝히면 `05-manuscript-final.docx` 저장.

저자 요청 시 아래 파일명으로 `.docx` 저장.
`.docx` 생성 전 반드시 `/mnt/skills/public/docx/SKILL.md`를 읽고 따른다.

## 원재료 활용 규칙

원재료란 블로그, 매거진, 뉴스레터, 강의 에피소드, 메모 등 저자가 이미 발행하거나 기록한 콘텐츠를 말한다.

1. **녹이기, 인용하지 않기**: 원재료를 그대로 옮기지 않는다. 경험과 사례를 책의 서사 흐름에 맞게 재구성한다.
2. **출처 표기 불필요**: 저자 본인의 글이므로 별도 출처 표기 없이 통합한다.
